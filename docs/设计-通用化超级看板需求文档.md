## 1. 目标与非目标

### 1.1 目标
- G1：任意表格型数据源（有表头 + 每行一条记录）都能生成可用看板——不限销售域
- G2：列映射语义由用户定义（维度/度量角色 + 自定义名称），不再锁定销售字段名
- G3：KPI 卡、派生指标、图表类型可配置可扩展（新图表以"注册制"加入，不改核心）
- G4：无时间列 / 无第二分类列的数据自动降级，不留空格子（明确规则）
- G5：向导体验延续（三步结构 + 图示 + 双层解释 + 自适应布局），学习成本不增加

### 1.2 非目标（本期不做）
- N1：不做多数据源合并看板（单表单源不变）
- N2：不做跨工作簿引用
- N3：不做实时刷新/外部数据库连接
- N4：不动现有销售链路的行为（向后兼容红线，见 §6）

## 2. 用户画像与典型场景

| 场景 | 数据形态 | 期望看板 |
|---|---|---|
| S1 库存分析 | 仓库/物品大类/入库日期/库存金额/库存数量 | KPI=总库存金额；趋势=入库日期；结构=物品大类 |
| S2 工资分析 | 部门/岗位/发放月份/应发/实发 | KPI=应发总额；趋势=按月；结构=部门占比 |
| S3 无时间数据 | 员工姓名/部门/绩效分/薪资 | 无趋势图→降级（见 FR-G4）；KPI=平均绩效/薪资总额 |
| S4 项目数据 | 项目名/负责人/状态/预算/花费 | KPI=预算执行率（派生）；结构=状态分布 |

## 3. 核心概念模型（泛化抽象）

- **维度（Dimension）**：文本/日期类列，用于分类与筛选。泛化后分三类角色：`时间维`（0 或 1 个）、`分类维1`（第一对比维度）、`分类维2`（结构占比维度）。数量 0~N，不再锁定"地区/品类"
- **度量（Measure）**：数值列，用于求和/计数/平均。泛化为 `主度量`（KPI 主角）+ `扩展度量`（0~N，用户勾选）
- **派生指标（Derived KPI）**：主度量/扩展度量四则运算（现有 extra_kpis 机制泛化，操作数=用户命名的度量）
- **槽位模型（⏳Q1 拍板对象）**：
  - 方案 A（自定义槽）：向导 Step1 改为「添加维度槽 / 添加度量槽」动态增删 + 用户自命名——彻底通用，改向导+服务两层
  - 方案 B（预设+通用双轨）：保留现有销售预设槽不动，新增「通用模式」N 维 M 度量——快但两套心智

## 4. 功能需求

### FR-G1 通用列映射（对应 ⏳Q1）
- 向导 Step1 支持：自动探测每列类型（数值/文本/日期，复用 create_super_table 既有类型规整），用户把列指派为 时间维/分类维/度量
- 度量可多选（≥1），维度可选 0~3 个；每个槽位显示探测出的类型徽标（数值/文本/日期），选错即时提示（如时间维选了文本列给"可自动转换"提示而非阻断）
- 列角色配置随超级数据表一并持久化（staging 元数据区新增一行角色清单），供后续工具读取

### FR-G2 通用 KPI 卡
- 默认 KPI 规则（⏳Q2 拍板）：
  - A. 全部度量自动求和生成 1~5 张卡
  - B. 向导里让用户勾选哪些度量上卡 + 聚合方式（求和/平均/计数）
- KPI 卡标题=用户命名的度量名；派生指标机制不变（操作数=度量名，四则 + 除零保护）

### FR-G3 图表注册制扩展
- 四宫格改为「图表槽」：每个槽=图表类型 × 绑定（维度/度量），预置 柱/条/饼/折线/环形/面积 六种
- 新增图表实现 `IBoardChart` 接口（输入：staging 区域引用 + 绑定配置；输出：Chart 对象），注册进图表工厂——后续加图不改渲染主链
- 绑定规则：柱/条/饼/环形/面积=分类维×度量；折线=时间维×度量（多时间维取第一优先）

### FR-G4 无时间维/少维度降级（⏳Q3 拍板确认）
- 无时间维：趋势槽自动替换为「条形·分类维 TOP10」（明确规则而非留白）；若分类维也没有→替换为「度量对比柱」（各度量一张柱）
- 无分类维2：饼图槽替换为「度量结构饼」（各度量占比）
- 仅剩 1 维 1 度量：四宫格收缩为 2 格（趋势 + 结构），KPI 卡保留——不硬凑四格

### FR-G5 向导改造（布局/图示/双层解释纪律延续）
- Step1 通用模式沿用 TableLayoutPanel 自适应 + WizardDiagram 图示（新增"通用映射"型示意图）+ 全控件双层 tooltip
- Step3 基础指标按钮区=用户命名的度量动态生成（不再是写死六个销售指标）

### FR-G6 工具契约
- 新增工具（⏳Q4 拍板改造 or 并存）：
  - `create_super_table` 泛化参数：`column_roles`（JSON：[{column, role: time|dim1|dim2|measure, alias}]）替代 label_column/category_column/...
  - `render_super_dashboard` 泛化参数：`kpi_cards`、`chart_slots`（JSON 绑定）、沿用 extra_kpis/theme/slicer_enabled/auto_rename
- 旧参数在过渡期继续支持（兼容层映射到 column_roles）

### FR-G7 服务端重构
- staging 汇总区按角色清单动态布局（列位置由元数据驱动，消除 C1/D1/E1 硬编码）
- KPI 区由 kpi_cards 配置驱动生成
- 探针套件扩批：SB6 通用数据用例（库存/工资/无时间/单维单度量 4 组）

### FR-G8 提示词与文档
- Schema 描述、系统提示词、用户手册、向导图示同步更新；AI 使用方可见"通用看板"工具说明

## 5. 非功能需求
- 性能：明细 ≤99998 行上限不变；staging 公式引用上限不变
- 日志：新链路沿用 AppLog 阶段打点 + ExcelTrace 异常留痕纪律
- 布局：向导新增控件全部走 TLP/Dock 自适应纪律（无 new Point）
- 验收：每批 gate 全绿 + SB6 探针 + 看图验收
