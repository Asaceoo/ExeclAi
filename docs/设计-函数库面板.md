# 设计：用户侧「函数库」侧边栏面板

> 版本 v2.19.0.0 · 状态：已实现 · 关联：`docs/技术手册`、`docs/踩坑记录与规避手册.md`
> 需求来源：参照 Excel「函数库」功能区（`插入函数 → 场景分类 → 其他函数兜底`）的编排逻辑，做**给用户人工浏览、按类插入 Excel 内置函数**的侧边栏面板。
> 版本（v2.19.0.0 补充）：函数库扩充至 312 个，新增**首版可用版本标注**（FX_VERSION 映射 + 版本筛选行 + 列表/详情版本徽章，范围 全部/2007/2010/2013/2016/2019/2021/365；未标注默认 2007）。
> 版本（v2.19.1.0 补充）：详情区三功能增强——**参数逐步讲解**、**示例试运行**、**相似函数对比**（见 §13）。

## 1. 目标与定位

在 WebView2 侧边栏新增一页「函数库」，让用户**不查帮助、不看文档**就能按业务场景找到 Excel 内置函数，点一下把公式骨架写进活动单元格。

**编排逻辑（取自 Excel 函数库功能区）**：
```
全局入口（插入函数）          →  本面板 = 搜索框（万能入口）
高频特权化（自动求和独立）    →  顶部「常用」快捷分类（SUM/IF/VLOOKUP/…）
8 大场景分类（色彩编码图标）  →  财务 · 逻辑 · 文本 · 日期时间 · 查找引用 · 数学三角 · 统计 · 其他
其他函数兜底                 →  搜索 hits「全部函数」
个性化（最近使用）            →  M2 版本落地（见 §9）
```

**本次只解决一个核心闭环**：`选单元格 → 找函数 → 插骨架 → 用户补参数`。

## 2. 非目标（显式排除，防范围膨胀）

- ❌ **不是** AI 运行时工具/技能（不注册成模型可调用工具，不占模型上下文）
- ❌ **不是** 又一个 AI 公式引擎（现有「公式面板」已做生成/解释/预览；本面板是**人工词典式插入**）
- ❌ **不是** 全量 450+ 函数词典（首版高频子集 + 搜索兜底）
- ❌ **不是** Ribbon 弹窗（舍弃，侧边栏承接）
- ❌ **不做** 参数对话框（仿 Excel Fx 参数框太重）
- ❌ **不** 强制 verify_formula 自检（客户端直写、模板静态可审计，见 §7）

## 3. 定位与边界：与「公式面板」的分工

| 能力 | 现有「公式面板」 | 新增「函数库」面板 |
|---|---|---|
| 消费方 | AI（大模型生成/解释） | 用户（人工点选） |
| 触发 | 输入需求 → AI 写公式 | 点分类/搜索 → 手动插骨架 |
| 落点 | 走 SendPrompt → AI 工具链（确认门） | 客户端直写活动单元格 |
| 价值 | 表达复杂业务意图 | 快速准确地插入内置函数骨架 |

两者**互补**：函数库是"我知道要哪个函数、只要正确写出它"的场景；公式面板是"我不知道怎么写、让 AI 代劳"的场景。

## 4. 整体交互流

```
用户选中单元格
  → 侧边栏底部导航切到「函数库」页（data-view="view-functions"）
  → 三种找函数方式：
       ① 键盘在搜索框打字（中文名/英文名/说明 模糊匹配）
       ② 点 8 大分类 chip（财务/逻辑/文本/日期/查找/数学/统计/其他）
       ③ 点「常用」快捷分类（高频 30~50 内置）
  → 右侧列表点「函数条目」→ 详情区展示：说明 · 参数(名/中/必填) · 示例
  → 点「插入」
       ├─ 目标活动单元格为空 → 直接插完整占位公式
       └─ 目标已有内容 → 前端轻确认（红色警告"将覆盖 X"）→ 批准才写
  → 通过宿主 InsertFormula 写入完整占位公式（如 =SUM(A1)，见 §8）
  → 前端提示"已插入 =SUM(A1)，请把 A1 替换为实际区域/参数"
```

## 6. 前端桥 API（复用现有 InsertFormula）

**不新增宿主方法**。函数库「插入」直接复用已有 `InsertFormula(targetAreas, formula)`（`SidebarBridge.cs` 3739 行）：

```csharp
public Task<string> InsertFormula(string targetAreas, string formula)
//  → targetAreas 可为空；空则用 CaptureCurrentSelectionAddress()（当前选区首格，即活动单元格）
//  → 内部 CreateHost().InsertFormulaToRange → 写公式 + 记录撤销快照
//  → 成功返回 { ok, inserted[], operation_ids[], history }（可回滚）
//  → 异常经 ExecuteAsync 返回 { ok:false, error }
```

**前端接入**：
```js
// 插入占位公式到当前选区首格；targetAreas 留空 → 宿主捕获当前选区
const r = parseResult(await asyncBridge.InsertFormula("", fxTemplate));
if(!r.ok) throw new Error(r.error);   // r.operation_ids 可用以回滚
```

**覆盖确认（写门）**：`InsertFormula` 走 `insert_formula_to_range`，属普通写入（不弹高危确认）且**不主动检查覆盖**目标已有内容。因此前端在点「插入」前先判目标：若当前选区已含内容，用**轻量确认**（本项目自建小确认条，**不复用**高危 `confirmOverlay`/`RespondConfirmation` 链路，避免混入模型确认编码）弹红色警告，批准后再调 `InsertFormula`。
- 判定目标非空：`parseResult(await asyncBridge.GetContext()).context.Selection` 读选区首个单元格 `Value2`（`GetContext` 宿主已存在）。
- **不做**"公式引用的区域被目标覆盖"连锁检查（复杂度高、收益低，弃）。

## 7. 写门与自检策略

- **写门（确认）**：默认只护「目标活动单元格已有内容」这一种覆盖。**不做**"公式引用的区域被目标覆盖"的连锁检查（复杂度高、收益低，弃）。破坏性语义与既有"允许执行"确认门一致，前端用红色警告。
- **自检**：插入经宿主 `InsertFormula → insert_formula_to_range` 落盘，自带撤销快照（`operation_ids`）与公式写工具的既定自检；它由**用户点面板**触发、非模型调用，不进模型工具覆盖审计。模板属静态、首版人工精编并真机抽查，从源头保证正确。
- **若未来**把"按函数插公式"开放成 AI 可调工具，则必须补 `MappedPrimaryTools`/豁免署名 + `verify_formula` 回读——本次不做。

## 8. 插入占位公式生成规则（正确性的关键约束）

- **落盘策略**：插入**完整占位公式**，直接复用宿主 `InsertFormula`——它是合法公式，Excel 直接接受并落盘。
- **占位生成**：`占位公式 = "=" + 函数名 + "(" + 必填参数的递增 A 引用占位 + 可选参数省略 + ")"`：
  - `=SUM(A1)`、`=LEFT(A1,1)`、`=VLOOKUP(A1,A2:B9,2,0)`、`=IF(A1,A2,A3)`、`=TODAY()`（无参直接可算）
  - 引用占位一律用 `A1/A2/…`（任意单元格，合法通用），用户落盘后直接替换为真实区域/参数。
- **绝不**把中文参数名或签名占位包（`number1,[number2],…`）写进单元格——`=SUM(number1,…)` 是未定义名称会 `#NAME?` 非法不可算。中文参数名与 `number1,[number2],…` **只**出现在详情/示例的展示文本里（§9 数据 `usage/params`），不进单元格。
- **占位期状态**：引用占位落盘后若区域内无数据，可能显示 `0`/`""`/`#N/A` 等"待替换"态，属预期，前端插入成功提示会说明"请替换引用占位"。
- 每个函数在数据 JSON 里预生成 `fxInsert` 字段（完整占位公式，见 §9），插入按钮直接取用，避免运行时拼写错误。

## 9. 数据资源（内置 JSON）

放置：前端内嵌静态对象（`index.html` 的 `<script>` 数据或独立 `.json` 资源），非运行时下载。

```json
{
  "category": "math",
  "name": "SUM",
  "title": "求和",
  "categoryCn": "数学和三角函数",
  "usage": "返回一组数值之和",
  "params": [
    { "name": "number1", "cn": "首个数或区域", "required": true, "desc": "第 1 个需要相加的数值/区域" },
    { "name": "number2", "cn": "后续数或区域", "required": false, "desc": "最多 255 个" }
  ],
  "example": "=SUM(A2:A10)",
  "exampleNote": "求 A2:A10 之和",
  "fxInsert": "=SUM(A1)"
}
```

- 高频子集：**30~50 个**，分至 8 大类 +「常用」。样例覆盖：数学(SUM/AVERAGE/ROUND/MOD…)、文本(CONCAT/LEFT/RIGHT/MID/TRIM…)、逻辑(IF/IFS/AND/OR/NOT…)、日期(TODAY/NOW/DATE/DATEDIF…)、查找(VLOOKUP/XLOOKUP/INDEX/MATCH…)、统计(COUNT/COUNTA/COUNTIF/SUMIF…)、财务(PV/FV/RATE…)、其他(INFO/SHEET…)。
- 搜索规则：命中 `name`(英文/不区分大小写) 或 `title/categoryCn/usage`(中文、模糊包含)。
- M1 每函数示例须**真机验证**（写进临时单元格回读核对），已被后续真机抽查覆盖。

## 11. 风险与纪要（联动踩坑手册）

- **非法公式**：中文参数名/中文函数名写格 = 非法公式 → 骨架只写英文函数名（§8，红线）。
- **覆盖用户数据**：默认只护目标单元格已有值，写前确认（§7）。
- **面板与公式面板混淆**：定位=人工词典，不是 AI 引擎（§3）。
- **COM 无状态/释放/线程**：新宿主方法遵守 §7 铁律 + §3.1 线程教训。
- **并行编辑同文件丢改**：本设计落地改 `index.html`/`SidebarBridge.cs` 多条编辑时，遵守踩坑手册 §9.1——同文件编辑串行、逐条核验。

## 13. 详情区三功能增强（v2.19.1.0）

> 目标：让**不查文档**的用户快速上手函数——把详情区从"说明书"升级为"带练手 + 帮选型"。

### 13.1 参数逐步讲解

- 把原有参数标签堆叠改为**编号步骤**（`fxLibPms`），每参一行：
  `① number1 — 首个数或区域 [必填] / ② number2 — 后续数或区域 [可选]`。
- 语义：照着"第几步填什么"就能把骨架补成可用公式，替代旧版一串小标签。

### 13.2 示例试运行（只算不改）

- 复用宿主 `PreviewFormula(formula, targetAreas)`（`SidebarBridge.cs` 3800 行）→ `worksheet.Evaluate` **在当前活动表上下文内实算**，返回值，**不写任何单元格**。
- 前端 `fxRunDemoFn`：点「▶ 试运行示例公式」→ 调 `asyncBridge.PreviewFormula(f.example,"")`（targetAreas 空 → 宿主捕获当前选区首格作上下文）→ 显示 `=SUM(A2:A10) = 15`。
- 边界：无示例公式 → 提示"该函数无示例公式"；Evaluate 异常 → 走 `{ok:false,error}` 或抛错，均落到红条 err 态；返回空值 → `#N/A（引用区为空）`。
- **注**：引用型示例（如 `=SUM(A2:A10)`）按活动表里 A2:A10 的**当前数据**实算，可能因区域无数据得 0/空，属预期（Effect：演示"公式如何算"，不改表）。

### 13.3 相似函数对比

- 新增内嵌 `SIMILAR` 映射（易混函数选型表，18 组，见 `index.html`），如 `SUMIF/SUMIFS`、`VLOOKUP/XLOOKUP/INDEX+MATCH`、`ROUND/ROUNDUP/ROUNDDOWN/TRUNC`、`LEFT/MID/RIGHT` 等。
- 详情区动态渲染「相似函数 · 该用哪个」卡片：**当前函数高亮** + 逐个语义一句话 + `fxWhenOf` 选型口诀（无口诀条目用通用兜底文案）。
- 命中 `SIMILAR[f.name]` 才显示对比块；其余函数隐藏，避免噪声。
