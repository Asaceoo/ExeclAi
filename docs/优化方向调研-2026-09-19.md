## 二、工程质量与技术债（不改会持续付利息）

| # | 方向 | 现状证据 | 价值 | 工作量 |
|---|------|---------|------|--------|
| B1 | **引入 git 版本管理** ⭐最高优先 | 无 .git（双副本备份模式）；9-17 插桩事故曾系统性损伤三工程源码且无备份，靠主副本逐段手术恢复——若当时有 git，`git checkout` 一条命令恢复 | 事故保险：任何脚本/编辑失误秒级回滚；也根治「双副本漂移」（主副本 3.7.1.47 vs WPS 副本 3.8.1.97） | 1 小时（init + .gitignore + 首次提交；不动开发流程） |
| B2 | **bump 历史叙事失真治理** | 已知系统性问题：bump 指针同步全局替换文档版本字符串，历史批次叙事里的「bump 3.8.1.9x」全部漂移成当前版本 | 交接文档可信度；根治法=叙事写日期不写版本号，或 bump 改为只替换指针表不碰叙事 | 半天 |
| B3 | **老内置技能 tools 登记漂移** | data-clean 等声明 `read_excel_range/read_excel_structure` 非真实注册名（真实为 get_excel_range_values_and_formulas 等），compat 徽章会误判「部分可用」 | 技能兼容性判定准确性；一行脚本批量 diff SKILL.md 声明 vs 注册表 | 半天 |
| B4 | **巨型文件拆分** | ExcelDashboardService.cs 5054 行、SidebarBridge partial 合计 5562 行、前端 index.html 4630 行（单文件含全部 JS） | 可维护性；partial 机械拆分已有先例（阶段 A 拆分）；前端可按 view 拆 JS 模块 | 分批，每文件半天~1 天 |
| B5 | **门禁进 CI** | §8 遗留项 6：单测关可挂 GitHub Actions（真机关需 Excel 留本机）；打包后自动打 tag | 防回归自动化；但本仓库无 git（依赖 B1） | 依赖 B1，半天 |
| B6 | **自检映射增量化**（§8 遗留项 1~5） | ①变换类 20+ 工具豁免转正（期望值可推导）②undo 后自动 verify（expected=快照 before_values）③clear 后 expected=空矩阵④筛选子集守恒⑤verify_file 映射导出系列 | AI 自检覆盖率从「映射表命中」走向「全覆盖」，每项都是十几行代码的小改动，可打包成一个批次 | 合计 1~2 天 |

## 四、优先级建议（按「价值/成本」比排序）

1. **B1 引入 git**——1 小时换掉整个项目最大的单点风险（再出一次插桩级事故就没有主副本可救了）
2. **A1 报告洞察 P0-1/P0-2**——需求已冻结、洞察宏已铺路，收尾工具层即可闭环
3. **B6 自检映射增量化**——五项小改动打包一批，AI 自检覆盖率跃升
4. **A2 MCP M-A**——1~2 天打开全新生态入口（Claude Desktop 直连）
5. **B2+B3 治理双项**——半天级，清掉两个已知漂移
6. **A4 通用化超级看板**——价值最大但需先 grill-me 拍板 Q1~Q7
