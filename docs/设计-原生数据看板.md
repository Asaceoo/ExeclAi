## 1. 背景与目标

用户诉求：在 Excel 内一句话生成"原生数据看板"——KPI 卡片 + 联动筛选 + 高级图表组合，效果对标杰瑞工具箱演示视频，但**全程 COM 晚绑定实现，不引入 VBA 依赖**（本项目 VBA 默认关闭）。

核心架构决策：**不让 AI 逐个调用写工具现场拼装看板**（每步都可能错、要确认、要自检，效果不稳定），而是：

```
用户一句话 ──► AI 产出 DashboardSpec（一份 JSON 规格书）
                    ▼
        render_dashboard(spec) 确定性渲染引擎，一次性生成
                    ▼
        verify_dashboard(spec) 自检，fail-closed
                    ▼
        失败 → 报错给 AI 修 spec → 重渲染（spec 幂等，重跑安全）
```

### 1.1 目标

- G1：AI 按看板模板目录选型 + 填参数，产出合法 DashboardSpec；
- G2：渲染引擎一次调用生成完整看板（数据/汇总/联动/图表/布局五层）；
- G3：`verify_dashboard` 断言图表存在、数据引用正确、联动重算对账，判定无期望值时 fail-closed；
- G4：全链路仅 Excel 宿主；WPS 侧按 D11 宿主感知过滤，不出现在工具清单；
- G5：新工具全部过 §6 门禁（覆盖审计 + 保护态守卫 + Excel 真机 harness）。

### 1.2 非目标

- N1：不做 WPS 宿主实现（D11 已定，不探测、不验证、不编排）；
- N2：不做透视表驱动看板（COM 编排复杂度高，SUMIFS 辅助区方案已够用，后续按需再议）；
- N3：不做图表动画/事件常驻监听（与无状态 COM 架构红线冲突）；
- N4：首批不求 67 套模板全量，精选 10-15 套覆盖 80% 场景。

## 3. 看板五层解剖与实现方案

| 层 | 内容 | 实现方案 | 复用现状 |
|---|---|---|---|
| ① 数据层 | 用户明细表 | 只读引用，不动 | 已有读工具 |
| ② 汇总层 | KPI 数值、维度聚合矩阵 | **SUMIFS 辅助区**（隐藏 sheet），图表全部指向辅助区，不碰明细 | 已有写入+公式模式 |
| ③ 联动层 | 地区/品类等筛选 | 方案 S：原生切片器（P0 探测通过才做）；方案 C：控制单元格 + 数据验证下拉（全版本兜底） | 数据验证已有 verify_data_validation |
| ④ 图表层 | 组合图、环形图、技巧型图 | 图表工具族扩展（§5） | 已有 5 种基础图 + verify_chart |
| ⑤ 布局层 | KPI 卡片、网格锚定、主题 | 合并单元格 + 填充色 + NumberFormat + ChartObjects.Add 网格锚定 + 关闭网格线 | 已有区域格式化 |

**纪律：③④层永远不直接引用明细数据，全部指向②辅助区**——联动只改控制单元格/切片器，SUMIFS 自动重算，性能与稳定性最优。

## 4. DashboardSpec Schema 草案

```json
{
  "version": 1,
  "template": "sales_overview",          // 模板目录 §5 中的 ID
  "source": { "sheet": "明细", "range": "A1:F500" },
  "theme": "orange",                      // 主题常量，首批 2-3 套
  "linkage": {
    "mode": "cell",                       // native | cell，P0 探测决定默认
    "fields": ["地区", "产品类别"],
    "control_cell": "看板!$B$2"
  },
  "staging": { "sheet": "_dashboard_calc", "hidden": true },
  "kpis": [
    { "title": "销售总额", "formula": "=SUMIFS(明细!F:F, 明细!B:B, 看板!$B$2)", "format": "¥#,##0", "sparkline": true }
  ],
  "charts": [
    { "type": "combo_dual_axis", "staging_range": "_dashboard_calc!A1:B7",
      "anchor": { "left": 24, "top": 120, "width": 480, "height": 280 } }
  ],
  "layout": { "hide_gridlines": true, "hide_staging": true }
}
```

要点：
- spec 为纯数据 → 可对"spec → 期望 COM 调用序列"直接做 xUnit 断言；
- 渲染幂等：重复渲染 = 先清理看板 sheet 再重建，回滚 = 删 sheet；
- AI 只做两件事：选模板、填参数。布局坐标由模板默认值兜底，AI 可覆盖。

### 4.1 三级校验链（2026-09-10 调研修订，源自 Vega-Lite NL→spec 流水线与行业收敛实践）

```
L1 spec 静态校验（渲染前，compile-before-render）
   ├─ 字段白名单：spec 只能引用模板定义的槽位（template/kpis/charts/linkage/theme），
   │   杜绝自由发挥字段——吸收语义字典（semantic dictionary）约束思想
   ├─ 类别数上限预检：环形/饼图 ≤5 类，条形 top-N 截断，超出 → 直接拒绝并给出
   │   替代建议（堆积百分比/截断柱），不进渲染
   └─ schema 结构校验：必填字段、anchor 数值范围、staging 引用格式

L2 渲染期校验（COM 执行中）
   └─ 每步操作失败即中止 → 清理半成品 → 分级错误码（对应交互稿 S6）

L3 verify_dashboard（渲染后，fail-closed）
   └─ 图表存在/类型/次轴/引用区域/守恒对账/联动重算（见 §6）

L4 verify_dashboard_deep（深度核验，只读，按需/回复契约触发）
   └─ 存在性/辅助表 KPI 重算/显示值守恒/数字卡片篡改扫描/联动控件/
      数值守恒对账（全量视图 KPI==源列直和）/图表渲染像素核验；
      每项输出 expected/actual/basis，verdict=任一 fail→mismatch（见 §6.1）
```

错误信息按 L1/L2/L3 分层给用户可读原因，不暴露 COM 裸错误码（AC-11）。

### 5.3 图表选型内置技能（借鉴杰瑞 SKILL 思路）

新增一个内置技能/流程模板：AI 拿到数据后先判形态再选模板——
- 时序对比 → 双轴组合；构成占比 → 环形/堆积百分比；
- 目标达成 → 子弹图/滑珠图；漏斗转化 → 漏斗图；
- 特大值压扁其余 → 截断柱；多维度交叉 → dim_cross 模板。

**选型规则表（2026-09-10 调研修订：Vega-Lite 工程实践、DataHub Pro 教程、双 Agent 报表系统三方一致，直接固化为技能规则文件）：**

| 数据形态 | 图表 | 约束 |
|---|---|---|
| 趋势/时序 | 折线 / 双轴组合 | — |
| 分类对比 | 柱形（横向多时用条形） | — |
| 占比构成 | 环形/饼 | **≤5 类**，超出转堆积百分比 |
| 分布 | 直方图（2016+）/ 柱形模拟 | 版本徽章 |
| 相关性 | 散点/气泡 | X 值走 XValues |
| 目标达成 | 子弹图/滑珠图 | — |
| Top N 排名 | 排序条形 | 默认 Top 10 截断 |
| 特大值悬殊 | 截断柱 | 柱顶 custom 标签标真实值 |
| 多维交叉 | dim_cross 模板 | 依赖 native 切片器（P0） |

规则以"拒绝并给替代建议"而非"静默降级"为原则（如分类数超限 → 拒绝环形，建议堆积百分比，对应交互稿 S6 场景）。

挂接现有 12 个内置技能基础设施，无需新框架。

### 5.4 KPI 卡渲染三件套（2026-09-10 调研修订，源自 DataHub Pro 成熟教程实践）

每张 KPI 卡默认内置三件套（模板默认值，AI 可关）：
1. **数值主体**：聚合口径 + 数字格式（`¥#,##0` / 百分比）；
2. **环比箭头**：`=IF(环比>0,"▲ "&TEXT(环比,"0.0%"),"▼ "&TEXT(ABS(环比),"0.0%"))` + 条件格式（正绿 `#1e9e6a` / 负红 `#d64545`）；
3. **可选迷你趋势**：KPI 卡下方 6 期 Sparkline（`SparklineGroups.Add`）。

**比率类 KPI 一律 IFERROR 包裹**（`=IFERROR(分子/分母, 0)`）——除零错误出现在汇报现场是不可接受缺陷，由渲染引擎强制注入，不依赖 AI 记得。

#### 6.1 verify_dashboard_deep 深度核验（FR-6.4，2026-09-11 交付）

只读工具（RiskLevel.ReadOnly，不进 MappedPrimaryTools——它不是写操作，是核验本身）：

| # | 检查项 | 判定 | 依据（basis 要点） |
|---|---|---|---|
| ① | 看板与辅助表存在 | 缺一 fail | 看板 = 可见看板 sheet + 隐藏 `_看板名_calc` 公式辅助表 |
| ② | 辅助表 KPI 重算 | 非数值 fail | SUMIFS/SUMPRODUCT 重算为文本/错误值 = 联动公式失效 |
| ③ | 看板卡片显示值守恒 | 显示值≠辅助表值 fail | 卡片公式引用辅助表单元格，IFERROR 回退「-」也算失真 |
| ③′ | 数字卡片篡改扫描 | 数字格式+文本常量 fail | 常量覆盖公式后 ③ 失明，数字格式+文本常量是公式被毁直接痕迹（U29/U31 实证：篡改必抓、常量目标值不误报） |
| ④ | 联动控件 | 下拉/切片器至少其一，否则 warn | 部分模板无联动，只提示不判失败 |
| ⑤ | 数值守恒对账 | 全量视图 KPI≠源列直和 fail | 筛选视图跳过（筛选语义聚合≠全量直和属正常） |
| ⑥ | 图表渲染像素核验 | 非白占比<1% warn | 图表导出 PNG 采样；空白图如实暴露（层级图引擎限制注记） |

verdict = 任一 fail → mismatch，否则 ok；checks[] 每项原样回显 expected/actual/basis，
SKILL.md「自检回复契约」要求 AI 最终回复逐项转述，禁止只说"正确"。

门禁义务：
- 全部入 `MappedPrimaryTools` 表态（新工具不表态就发不出去）；
- `SheetProtectionGuard` 前置探测，render 类豁免需带理由；
- `verify_dashboard` 断言：图表存在且类型正确、staging 引用区域正确、次轴存在、KPI 值 == SUMIFS 重算值（守恒对账口径）、联动切换后重算生效；判定无期望值 fail-closed；
- Excel 真机 harness 新增用例组；WPS full 基线不受影响（工具被过滤，基线分布不变）。

## 7. 分期路线

| 期 | 内容 | 成本 | 效果 |
|---|---|---|---|
| P0 | Slicer 原生支持探测 harness（仅 Excel，只读） | 半天 | 消灭联动方案最大不确定性 |
| P1 | 第一批图表工具 + `kpi_brief` 静态看板 | 2-3 天 | 视频效果 70%，可出 demo |
