# JYYJ助手 功能区命令组需求文档

- 目标版本：2.2.0.0（下一 minor）
- 文档日期：2026-08-28
- 状态：待评审

## 1 版本与定位

本需求为**纯增量**特性，新增功能区命令组，把项目已有的高频本地能力做成"选中即用"的一键入口。三个硬约束贯穿全程：

1. **不改既有功能**：现有「JYYJ助手」Tab 及其"打开面板"按钮原封不动；侧边栏、聊天、工具、工作流、自检体系零改动。
2. **离线优先**：新增命令组默认直调本地工具（Excel COM + 本地 SQLite + 本地 Python worker），不依赖模型端点；仅个别需 AI 理解的功能保留在线路径。
3. **可回退**：新增元素集中在独立 Tab 与新组件内，卸载或禁用即可整体回退，不触碰既有注册链。

## 2 背景与目标

竞品借鉴调研（方方格子）把"免对话直达入口"列为 P0 缺口：本项目全部能力收敛在侧边栏对话内，高频操作必须打字让 AI 执行，缺少"选中区域、点一下按钮、立即完成"的路径。

现状基础设施已具备：功能区仅一个 Tab + 一个"打开面板"按钮，但 `ExcelAiAddIn.cs` 中残留 `OnExplainFormula`/`OnAiFillBlanks` 旧回调，说明功能区扩展框架完整可用；同时工具注册表已有 10+ 个纯本地高频工具（删除空行、去重、拆分合并、填充序列、透视等），可直接映射为按钮，不经过 AI。

目标：

- 高频确定性操作 ≤2 次点击完成，不经过对话。
- 新增命令全部可离线运行。
- 不改变任何既有交互路径，不引入新依赖。

## 3 总体方案

### 3.1 功能区布局

新增独立 Tab「JYYJ快捷」，承载 5 个命令组；现有 Tab 保持不动。

```
┌ Tab: JYYJ快捷 ─────────────────────────────────────────────────────────────┐
│ 视图组        数据处理组      文本组      常用组              更多组        │
│ ┌───────────┐ ┌─────────────┐ ┌────────┐ ┌──────────────────┐ ┌──────────┐ │
│ │ 聚光灯 toggle │ 清洗   去重 │ │ 拆分合并 │ │ 删除空行 填充序列 │ │ 宏收纳箱 │ │
│ │ 指针   toggle │ 排序   转置 │ │ 清理填公式│ │ 删除文本 填充随机 │ │ 函数库   │ │
│ │              │ 筛选   透视 │ │        │ │ 隔行插空 合并相同 │ │ SQL 查询 │ │
│ └───────────┘ └─────────────┘ └────────┘ └──────────────────┘ └──────────┘ │
└────────────────────────────────────────────────────────────────────────────┘
```

按钮形态：视图组用 `toggleButton`（开/关两种状态），其余全部用 `button`（单击执行）。

### 3.2 执行模式契约

| 模式 | 接线 | 离线 | 适用 |
|---|---|---|---|
| A 直调工具（主） | 按钮 → `RibbonCommandService` → `ExcelToolHost` 本地执行 | 是 | 全部高频确定性操作 |
| B 注入提示词（辅） | 按钮 → 既有聊天注入意图，AI 编排执行 | 否 | 公式讲解、语义填充建议 |

模式 A 是新增接线，不触碰既有聊天链路；模式 B 复用既有 `InjectRibbonPrompt`，仅新增按钮入口。两种模式互不干扰，可混用。

## 4 功能需求详述

### 4.1 视图组：聚光灯 / 指针

**布局**：两个 `toggleButton`，图标用 Office 内置 `imageMso`（如 `ReviewShadingColorPicker` 系），不引入图片资源。

**聚光灯**：用户点击后开启"阅读模式"，活动单元格所在整行整列被浅色高亮，其余区域弱化；再次点击关闭。实现上订阅 `SelectionChange` COM 事件，移动单元格时高亮跟随；切换工作表时重新计算高亮区域；开启状态下若发生整行/整列删除等破坏性操作，高亮自动重建。关闭时彻底移除高亮与事件订阅，不留残留状态。

**指针**：开启后活动单元格显示一个跟随的指针/标记框（边框高亮），用于定位当前编辑位置；关闭即移除。与聚光灯互斥：开启其中一个自动关闭另一个。

**边界**：两个功能都是视图层叠加，不写入任何单元格数据，撤销栈无痕；合并单元格、隐藏行列区域不产生高亮，避免误渲染。

**验收**：开启后移动活动单元格高亮实时跟随；切换工作表不报错且正常重建；关闭后工作簿完全恢复原样；两个 toggle 互斥联动正确。

### 4.2 数据处理组：清洗 / 去重 / 排序 / 转置 / 筛选 / 透视

**布局**：六个 `button`，映射到既有工具：`clean_excel_data`、`dedup_range`、`sort_range`、`transpose_range`、`filter_excel_data`、`create_pivot_table`。

**通用行为**：按钮以**当前选区**为输入。选区为单个矩形区域时直接执行；选区为空或未选中时弹提示"请先选中数据区域"；非矩形选区按既有硬约束拒绝并提示"请选择矩形区域"。

**清洗**：对选区执行 `clean_excel_data` 默认规则（去除首尾空格、统一空白、修正常见脏数据），结果写回原区域。执行前按工具自身 RiskLevel 走确认门。

**去重 / 排序 / 转置 / 筛选**：分别调用对应工具，使用选区推断默认参数（去重默认整行判重并保留首次出现；排序默认按首列升序；筛选默认按首列不等于空）。排序与筛选为破坏性写回操作，必须过确认门。

**透视**：调用 `create_pivot_table`，默认以选区首列为行标签、自动探测首个数值列汇总，目标表放置在选区下方 2 行；生成后按既有 `verify_pivot` 自检并展示结果摘要。

**边界**：所有操作沿用既有工具的写入范围与安全约束（表头从第 2 行起、非 A1 原点坐标偏移、失败回滚），本需求不修改工具本身逻辑，只新增按钮直调入口。

**验收**：对样例区域点每个按钮，结果与侧边栏对话里让 AI 执行同一工具一致；破坏性操作均弹出确认门；自检 verdict 正确展示。

### 4.3 文本组：拆分 / 合并 / 清理 / 填公式

**布局**：四个 `button`，映射 `text_split`、`text_merge`、`text_clean`、`fill_formula`。

**拆分**：对选区首个文本列按默认分隔符（逗号）拆到右侧空列；若右侧无空列，弹提示说明需要预留目标列。拆分结果以"仅目标列写回"方式落地，不覆盖源列。

**合并**：将选区内多列文本按分隔符合并到首个空列。

**清理**：对选区执行 `text_clean`（去空格、统一换行、去重复空格），原地写回。

**填公式**：对选区中每个空单元格填充与上方单元格相同的公式引用（相对引用智能下移），适用于"整列套用公式"场景。

**边界**：拆分为横向扩展写回，涉及右侧列时需确认目标区域是否为空，非空则拒绝并提示，防止覆盖数据。

**验收**：拆分不覆盖源列；合并到空列；清理原地生效；填公式后单元格引用随行号正确偏移。

### 4.4 常用组：JYYJ 高频工具

**布局**：八个 `button`，直接映射 `ExcelJyyjtool` 系列工具——删除空行（`delete_blank_rows_range`）、删除文本（`delete_text_matches`）、填充序列（`fill_number_sequence`）、填充随机数（`fill_random_numbers`）、向下填充空单元格（`fill_blank_cells_down`）、隔行插空行（`insert_blank_rows_every_n`）、合并相同单元格（`merge_duplicate_cells`）、插入文本（`insert_text_into_cell`）。

**通用行为**：以当前选区为输入，使用默认参数（删除文本默认空值参数弹迷你输入框；隔行插空默认隔 1 行插 1 行；填充随机数默认 1–100 整数），执行后展示"处理 N 行"式结果摘要。

**参数输入**：需要参数的按钮（删除文本、插入文本、填充随机数、填充序列）弹轻量输入框收集参数；用户可随时取消，取消则按钮不执行、状态无变化。

**边界**：这些工具全部为进程内本地执行，离线可用；其中删除空行、隔行插空、合并相同单元格会改变行结构，必须过确认门。

**验收**：八按钮逐一在样例数据上验证，结果与侧边栏执行同工具一致；参数输入框可取消；行结构变更类均弹确认门。

### 4.5 更多组：宏收纳箱 / 函数库 / SQL 查询

**布局**：三个 `button`，作为**入口**而非就地执行，打开侧边栏对应页面或注入模板。

**宏收纳箱**：点击后打开侧边栏"宏收纳箱"页（按场景分类浏览、收藏、管理已沉淀的 VBA 宏与 Python 模板）。本版本只做入口与页面展示，收纳箱页面本身按独立需求排期。

**函数库**：点击后打开侧边栏"JYYJ 函数库"页，展示已注册的工作表函数（`JYYJ.*`）列表与用法示例，支持复制函数文本回单元格。**边界说明**：UDF 函数注册是独立机制（COM 函数暴露），不属于功能区命令组；本按钮只承担浏览与插入辅助入口。

**SQL 查询**：点击后打开 PT 面板（Python 脚本面板），预填 SQLite 查询模板（读取当前工作簿为库、选区为表），用户确认后由 Python worker 本地执行。模板预填遵循既有"预置模板用 `sheets.active` 活动表"约定。

**验收**：三按钮正确打开对应页面/模板；SQL 模板含当前工作表名与选区引用；函数库页正确列出已注册函数。

## 5 执行接线方案

新增组件 **`RibbonCommandService`**（位于 `ExcelAiAssistant.Addin`），职责：

1. 持有一个进程内 `ExcelToolHost` 实例（与侧边栏同一构造方式 `new ExcelToolHost(excelApplication)`），供模式 A 直调工具。
2. 统一执行入口 `ExecuteTool(toolName, selection, args)`：解析当前选区 → 校验矩形/非空 → 组装默认参数 → 按工具 RiskLevel 决定是否弹确认门 → 调用工具 → 收集结果与 `verify_*` 自检 verdict → 反馈到侧边栏日志。
3. 聚光灯/指针的 COM 事件订阅与清理独立封装，严格无泄漏（复用既有 RCW 无状态访问纪律）。
4. 与既有代码的接触面仅三处，全部只增不改：`Ribbon.xml` 追加 Tab；`ExcelAiAddIn.cs` 追加回调方法；`SidebarBridge` 注入日志通道。不修改任何既有方法体。

模式 B 的按钮（公式讲解、智能填充建议）复用既有 `InjectRibbonPrompt` 一行接线。

## 6 验收标准

1. 全新 Release 构建（x64/x86）0 警告 0 错误，既有 684 项单测全部通过，新增 Ribbon 相关单测覆盖选区解析与参数默认值逻辑。
2. 真机验证：功能区出现新 Tab「JYYJ快捷」，5 个命令组按钮齐全；现有「JYYJ助手」Tab 与"打开面板"按钮行为与安装前逐项一致。
3. 逐个按钮离线执行成功：拔网线（或断开模型端点）状态下，模式 A 全部按钮可用，结果正确。
4. 聚光灯/指针开启、移动、切表、关闭全程无报错，关闭后工作簿恢复原样，无残留进程（Excel PID 检查）。
5. 破坏性操作（排序、筛选、删除空行、隔行插空、合并相同）均触发确认门；非矩形选区被拒绝并提示。
6. 安装/卸载冒烟：安装后功能区加载正常；卸载后新 Tab 与注册项一并清除，既有数据与配置保留。
7. 真机验证日志自检：`verify_*` 自检在按钮执行后正确记录 verdict，无 no_expected/无判定依据告警。

## 7 安全与风险

- **风险面最小化**：新增组件与既有功能解耦，唯一共享点是工具注册表（只读引用）与日志通道（只增）。
- **COM 泄漏**：聚光灯事件订阅、工具直调均沿用既有 RCW 无状态纪律与 PID 清理，防残留 Excel 进程。
- **误操作保护**：行结构变更类与写回类操作一律过确认门，与既有对话路径的安全级别一致。
- **离线兜底**：模式 A 不依赖网络与模型，无 AI 可用时功能不受影响；模式 B 离线时按钮置灰并提示原因。

## 8 开放问题

1. **聚光灯实现代价**：COM `SelectionChange` 事件订阅需要新增事件接收器，工作簿多开（多个 `Workbook` 同时开启）时高亮作用域如何界定——先只作用于活动窗口，多开支持按需扩展。
2. **参数输入框形态**：迷你输入框（HTML 弹窗）还是复用侧边栏页面——推荐迷你弹窗，避免打断"点一下"的节奏，需评审确认。
3. **函数库独立排期**：UDF 注册本身是否纳入本版本，还是仅做入口与展示页——本需求默认后者，UDF 注册另立需求。
4. **收纳箱页面**：本需求只做入口，收纳箱可视化页面是否与 Ribbon 一起排期，待确认。
