# JYYJ快捷 功能区（第一批）需求文档

- 目标版本：2.19.0.0（下一 minor）
- 文档日期：2026-09-06
- 范围：数据处理组 + 文本处理组（导出打印组、常用 JYYJ 组另行排期）
- 状态：已评审（经 /grilling 拷问收敛）

---

## 1 定位与核心约束

### 1.1 一句话

给 JYYJ助手 新增独立功能区 Tab「JYYJ快捷」，把高频本地工具做成**选中区域→点按钮→弹参数→执行**的一键入口。**任何人接手（包括离职交接）都能用**：纯本地、零模型、零账号、断网可用。

### 1.2 四项核心决定（经拷问锁定）

| 决策点 | 结论 | 理由 |
|---|---|---|
| 执行范式 | 需要参数的工具**弹 HTML 参数框**；无需参数的一键直跑 | 排序要选列、拆分要分隔符、透视要行列，纯默认直跑不贴合 |
| 确认门 | **不过全局确认门，改靠回滚兜底**；但**删行类结构性操作二次确认** | 保留"点一下即成"体验，同时防误删整表 |
| 自检 | **不触发 AI verify 自检**；但**保留操作历史 + 写改日志 + 可回滚** | 满足轻量入口诉求，又不丢可左证基线 |
| 参数默认 | 参数框内可**配置**去重键 / 排序列 / 透视行列等；提供下拉选列 | 用户可自行决定"按哪里" |

### 1.3 硬约束

1. **不改既有功能**：现有「JYYJ助手」Tab（打开面板 + 聚光灯/指针）原封不动；侧边栏、聊天、工作流、自检体系零改动。
2. **严格离线**：所有按钮走进程内 Excel COM 本地工具，不依赖模型端点、不请求网络。
3. **可回退**：新元素集中在独立 Tab 与独立组件，卸载或禁用即整体回退。
4. **回滚兜底**：每个按钮执行都写操作历史（OperationRepository），执行后可在历史面板回滚；运行日志留痕。

本批共 **10 个按钮**，全部为 `button`（单击），映射既有本地工具。

## 3 数据处理组（6 个）

### 3.1 通用交互

所有按钮以**当前选区**为输入。统一前置校验（复用既有硬约束）：

- 选区为空 / 未选中 → 提示"请先选中数据区域"。
- 非矩形选区 → 拒绝并提示"请选择矩形区域"。
- 需要参数的按钮 → 弹 HTML 参数框，参数框内提供选区列名下拉；可取消（取消则零执行零变更）。

参数框校验通过后 → 调工具 → 展示结果摘要（"处理 N 行 / 输出到 XXX"）→ 写入操作历史（可回滚）。

### 3.2 数据流向约定（本批关键决策）

- `清洗`：**原地写回**（clean_excel_data 对 address 就地清洗）。
- `去重 / 排序 / 转置 / 筛选`：**原地写回原区**（dedup_range / sort_range 对当前选区写回）。
- `透视`：**输出到新区**（create_excel_pivot_summary 的 target_address 默认放源区下方 2 行；透视输入含标题行）。

> ⚠️ 上述"原地写回"为筛选/排序等会被覆盖源区的操作，均属破坏性写回 → 依据 §5 分级处理。

### 3.3 各按钮参数与行为

| 按钮 | 底层工具 | 参数框提供 | 默认 | 破坏性 |
|---|---|---|---|---|
| 清洗 | `clean_excel_data` | 勾选清洗维度：去空行 / 修日期 / 填空白 | 三项全选 | 否（原地，安全） |
| 去重 | `dedup_range` | 判重范围：整行 / 指定列(下拉选列)；保留：首次/末次 | 整行·首次 | 是（删重复行）|
| 排序 | `sort_range` | 排序列(下拉)；升/降序；是否含表头 | 首列·升·含表头 | 是（重排行）|
| 转置 | `transpose_range` | 目标：原地左上位 / 指定位置 | 原地左上位 | 是（重排）|
| 筛选 | `filter_excel_data` | 条件列(下拉)；运算符(= / ≠ / 包含 / > / ≥ / < / ≤ / 空 / 非空)；值 | 首列·↑null 跳过 | 是（覆盖源区输出）|
| 透视 | `create_excel_pivot_summary` | 行标签列(下拉)；数值列(下拉，默认自动探测首个数值列) | 首列为行·自动数值 | 否（写新区）|

## 4 文本处理组（4 个）

| 按钮 | 底层工具 | 参数框提供 | 默认 | 破坏性 |
|---|---|---|---|---|
| 拆分 | `text_split` | 源列(下拉)；分隔符；保留/清空源列 | 首列·逗号·保留源列 | 否 |
| 合并 | `text_merge` | 参与列(多选下拉)；分隔符；跳过空 | 前两列·空格·跳过空 | 否 |
| 清理 | `text_clean` | 清洗项：去首尾空格 / 合并空白 / 去控制字符 / 统一大小写 / 删指定字符 | 去首尾空格+合并空白 | 否 |
| 填公式 | `fill_formula` | 公式模板（用 `{row}` 表示当前行号）；区域 | 选区 | 否 |

**拆分边界**：拆分结果为横向扩展写回右侧列；若右侧目标列非空，提示需预留空列，拒绝覆盖。

## 5 安全分级（本批落地后）

| 类别 | 行为 | 处理 |
|---|---|---|
| 安全写回（清洗/文本四工具/透视/转置写新区） | 不删行、不覆盖用户其他数据 | 直接执行，记历史可回滚 |
| 覆盖写回（排序/筛选原地覆盖源区） | 覆盖原区数据 | 执行前参数框内黄字提示"将覆盖原区域" |
| 删行类结构性（去重删重复行） | 物理删行 | **参数框内二次红色警示"将删除 N 行，确定？"需再次点击** |

特殊：本批去重是唯一删行类 → 走二次确认；其余均为覆盖或安全写回。

## 6 执行链路与组件

新增 **`RibbonCommandService`**（位于 `ExcelAiAssistant.Addin`，作为整体方案预留）：

1. 持有一个进程内 `ExcelToolHost` 实例（与侧边栏同一构造 `new ExcelToolHost(excelApplication)`）。
2. 统一入口 `ExecuteTool(toolName, sourceSelection, args)`：
   - 解析当前选区 → 矩形/非空校验 → 组装参数（默认值/参数框覆盖）→ 安全分级判定（§5）→ 二次确认（仅删行类）→ 调工具 → 写操作历史 → 回结果摘要。
3. 参数框为 **HTML 弹窗**（复用侧边栏 WebView2 技术栈做静态组件，离线下可用；下拉选项由 C# 注入当前选区列名）。
4. 与既有代码接触面仅三处，全部只增不改：
   - `Ribbon.xml` 追加 Tab「JYYJ快捷」；
   - `ExcelAiAddIn.cs` 追加回调方法；
   - `SidebarBridge` 注入操作历史/日志通道。
5. **不触发** AgentRunner 的 `verify_*` 自检路径——功能区直调本地工具，不经过模型。自检缺口由"操作历史 + 日志留痕"兜底（§8 有明确取舍说明）。

## 7 验收标准

1. `dotnet build ExcelAiAssistant.sln` 0 警告 0 错误；新增单测覆盖选区解析、参数框校验、二次确认判定。
2. 真机：功能区出现「JYYJ快捷」Tab，2 组 10 按钮齐全；既有「JYYJ助手」Tab 行为与安装前一致。
3. 逐个按钮离线执行：拔网状态下全部可用，结果正确。
4. 破坏性判定正确：去重弹二次红色确认；排序/筛选弹"将覆盖原区"提示；清洗/文本/透视直接执行。
5. 所有执行写入操作历史，可在历史面板回滚；回滚后数据恢复原值。
6. 非矩形选区被拒绝并提示"请选择矩形区域"；空选区提示"请先选中数据区域"。
7. 参数框可取消，取消后无任何变更；拆分到非空右侧列被拒绝。
8. 安装/卸载冒烟：卸载后新 Tab 与注册项一并清除，既有数据与配置保留。

## 8 与既有自检体系的关系（明确取舍）

项目长期目标是"写入可左证"。本批功能区按钮为保住"一键/交接可用"体验，做了以下取舍，**全部有落点**：

- ❌ 不走模型驱动的 `verify_*` 自检（无 AI 参与，无模型给付）。
- ✅ **每一个写操作**仍进 `OperationRepository` 写入历史面板 → 可回滚（与对话路径同机制）。
- ✅ 执行写入运行日志（DiagnosticsLog）留痕，级别可查。
- ✅ 覆盖性写回/删行类在入口做分级 + 红色警示（安全左证前置而非事后核对）。

因此本批不破坏、也不依赖第 4 节自检体系；两者是"轻量入口 + 既有可左证基建"的关系。若后续某个按钮确实需要较强的结果核验，可在参数框内加"执行后自检"可选项单独排期（本批不做）。
