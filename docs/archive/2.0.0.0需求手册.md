## 一、产品定位

### 1.1 一句话定位

面向 Windows Excel 的本地智能办公 Agent。用户在 Excel 侧边栏用自然语言下达指令，系统感知当前工作簿、工作表和选区，调用受控工具完成读取、分析、写入、格式化、透视表、图表、数据清洗与脚本执行，并通过操作历史支持回滚。

### 1.2 目标用户

| 用户 | 核心诉求 | 优先级 |
|---|---|---|
| 财务、审计、运营人员 | 清洗底稿、汇总数据、复核公式、生成分析结果 | P0 |
| 普通办公用户 | 理解表格、生成公式、做简单图表 | P0 |
| 高级办公用户 | 批量整理、目录页、Markdown 转换、复杂自动化 | P1 |
| 开发/数据分析人员 | 运行 Python/VBA 脚本、扩展 Skill、用 pandas 处理 Excel 数据 | P2（2.0.0.0 起放开） |

### 1.3 版本边界

- 操作对象：Excel 当前已打开的工作簿；`.xlsx` / `.xlsm` / `.xls` 均可处理。
- 不承诺：后台批量处理未打开文件、WPS 表格兼容、Mac/Web Excel、多语言界面、在线授权订阅。
- 2.0.0.0 新增边界：Python 直连仅作用于「当前 Excel 实例」的活动工作簿；依赖安装需用户确认。

### 2.2 安全与撤销

- 风险分级 L0–L3：读取自动执行；普通写入 diff 确认；删表/删行列/脚本执行默认不可用，高危开关显式开启后逐次确认。
- 写前快照：普通区域记录新旧值（≤500 cells）；大变更与删除类自动完整备份（7 天）。
- 操作历史：SQLite 保存会话/消息/工具事件/操作记录，支持回滚。
- 受控执行：`ControlledExecutionConfig` 总开关；脚本超时（默认 30s）、输出截断（默认 64KB）、`input()` 禁用、网络禁用。
- 数据隐私：默认采样与摘要发送；敏感格式（身份证/手机号/银行卡）正则提醒；API Key DPAPI 加密。

### 2.3 脚本执行现状与短板（2.0.0.0 要补的）

| 链路 | 现状 | 短板 |
|---|---|---|
| `run_vba_snippet` | 受控执行，探针回 `OK` / `ERR|num|desc` | 结果只有文本；拿不到外部入参；无跨调用状态 |
| `run_python_code` | 常驻 worker 纯计算，回 stdout 文本 | 碰不到 Excel；数据进出靠拼字符串；无跨调用状态 |
| 两者之间 | 无数据通道 | 多步「Python 算→VBA 写」只能靠 AI 手动串联 |

## 三、2.0.0.0 新增能力（Python 版主线）

### 3.1 结构化结果回传（VBA + Python）

**目标**：让执行器把「计算结果」结构化地交回 AI，而不是只回一段 stdout 文本。

| 编号 | 需求 |
|---|---|
| A1 | **VBA 结构化回传**：VBA 片段内调用辅助函数 `XaiReturn value`（注入草稿模块），把任意值（标量/数组/字典）序列化为 JSON 存入模块级变量；探针在 `Application.Run` 后读取，按 `OK|<json>` 协议回传；C# 侧解析为结构化 Data |
| A2 | **VBA JSON 序列化器**：自研轻量序列化器，支持嵌套数组/字典/标量，不依赖第三方库；失败时回退 `OK` 并标记 `result_serialize_failed` |
| A3 | **Python 结构化回传**：worker 注入 `xai_result(obj)` 到执行命名空间；调用后把对象 JSON 序列化进 reply 的 `result` 字段（不占 stdout）；C# 侧作为结构化 Data 返回 |
| A4 | **stdout 与 result 分离**：stdout 保留给人读的文本，result 是机器可读结构化数据；超大 stdout 截断不影响 result |
| A5 | **回传体积护栏**：result 序列化后超上限（默认 1 MB，可传 `result_limit_kb`）时截断并标记 `result_truncated` |

**验收**：`XaiReturn Array(1,2,3)` 后 AI 拿到 `result:[1,2,3]`；`xai_result({"a":1,"b":[1,2]})` 后 AI 拿到结构化 dict/list；未调用回传函数的旧片段行为不变；超大 result 截断不抛异常。

### 3.2 数据双向通道（Excel ↔ 脚本）

**目标**：让脚本能拿到 Excel 选区数据、算完再写回，形成「Excel→脚本→Excel」闭环。

| 编号 | 需求 |
|---|---|
| B1 | **Python 入参通道**：`run_python_code` / `run_python_excel` 支持 `input_data`（JSON 或二维数组），注入执行命名空间的 `input_data` 变量 |
| B2 | **VBA 入参通道**：`run_vba_snippet` 支持 `args`（JSON 对象），序列化注入草稿模块模块级变量 `gXaiArgs`；VBA 用 `XaiArg("key")` 读取 |
| B3 | **入参护栏**：`input_data` 超上限（10 万 cell 量级）显式 `Invalid("INPUT_TOO_LARGE")` |
| B4 | **出参合拢**：脚本结果经 3.1 结构化回传；写回由 AI 编排既有写工具或 `run_python_excel` |
| B5 | **数据形态**：二维数组/JSON 对象/标量统一支持；空值、日期、文本型数字的往返语义写清（对照「日期串写回变数值」教训） |

**验收**：读选区→传 Python 计算→返回结构化结果→写回，全链路数据不丢、类型不串；`XaiArg("column")` 行为与硬编码一致；超大 `input_data` 显式拒绝。

### 3.3 Python COM 直连 Excel（`run_python_excel` 新工具）★ 核心亮点

**目标**：让 Python 原生读写当前 Excel 实例，替代部分 VBA 场景，用 Python 语法与生态（pandas/numpy）。

| 编号 | 需求 |
|---|---|
| C1 | **新工具注册**：`run_python_excel`，schema 独立（`code` / `timeout_ms` / `output_limit_kb` / `write_ranges` 可选），风险等级 Dangerous，受控执行总开关 |
| C2 | **库双轨**：xlwings 为主 API（`import xlwings as xw`），pywin32 为底层兜底（`win32com.client.GetActiveObject`）；两者缺失走依赖自动安装 |
| C3 | **连接活表**：worker 注入连接代码，`xw.apps.active` 连当前实例、`xw.books.active` 定位活动簿；失败给出可读错误（区分「Excel 未运行」「实例不可 COM 访问」「库缺失」） |
| C4 | **写回纪律**：Python 直写绕过 `OperationRecorder`，靠确认门兜底；AI 声明 `write_ranges` 时执行前快照该区域供回滚 |
| C5 | **依赖自动安装**：首次使用检测 `import xlwings` / `import win32com`，缺失时提示并 pip 安装（用户确认）；已装则跳过（幂等） |
| C6 | **与 `run_python_code` 边界**：`run_python_code` 保持纯计算低风险；`run_python_excel` 可操作 Excel 高风险；schema 描述如实写明差异 |
| C7 | **worker 复用**：复用 `PythonWorkerHost` 常驻架构，注入 Excel 连接上下文；连接失败/Excel 重启自动重建 worker |
| C8 | **按选区画图**：`run_python_excel` 内用 xlwings 在活动工作簿活动表创建**原生 Excel 图表**：`sht.charts.add()` + `chart.set_source_data(sel_range)` + `chart.chart_type` 指定类型（如 `column_clustered`）；`sel_range` 为 PT 面板「插入选区」注入的选区地址（兼容 `globals()['sel_range']` 缺省回退）；`chart_type`/`chart_title` 可选注入覆盖类型与标题；多选区注入取首块画图；结果经 `xai_result` 结构化回传图表名、类型、实际使用区域与是否设标题 |

**验收**：`xw.books.active.sheets[0].range("A1").value = 42` 写入当前活动簿；读选区计算后写回另一区域，全程不拼字符串；未装库时首次调用触发安装引导；连接失败给出可读错误；与 `run_python_code` 边界清晰。**画图**：选区数据经 xlwings 生成原生 Excel 图表，可读回数据源绑定选区、类型正确、计数递增；预置模板 `py_chart_selection` 真机可跑。**图表自检**：生成任何图表后调用 `verify_chart` 形成闭环，自检维度已真机验证（VVC-1~8 全 PASS）：图表真生成（chart_found）、系列/数据点有效性（expected_series）、类型族比对（expected_chart_type）、标题比对（expected_title）、数据源比对（expected_data_source，按 series 公式相交判定）、像素级渲染核验（导出 PNG 算非白像素占比并返回 chart_image 供 AI 肉眼核对）；类型不符 → verdict=mismatch、标题不符 → title、数据源不符 → source、系列数不符 → 追加提示性 issue（不改 verdict），并返回 verdict+issues+selfcheck 三要素。

**A 补齐自检**：新增 `verify_write_result`（写入结果：期望值矩阵逐格比对 + 非空单元格数）、`verify_data_clean`（清洗：无整行空白/指定列无空白/无重复/日期列有效/无文本型数字，`columns` 指定列时对全部非空文本严格做日期解析，避免姓名/备注列误报）、`verify_pivot`（透视表：标签逐行抽查汇总值 + 数据行数，`target_address` 单格自动扩展 CurrentRegion）、`verify_marker`（标记：被标记总数 + 标记色集合 + 期望地址命中）四工具，全部只读、返回 verdict+issues+selfcheck 三要素，已真机验证（VVT-A1~A4 全 PASS，含「期望给错必须报 issue」的反向断言）。

**B 流程自检注入**：`WorkflowStep` 增 `Verify` 规格，`run_workflow` 主步骤成功后自动执行对应 verify 工具并校验 verdict——达标放行、未达标停在当前步（可单步重试重跑主步骤+自检）；`Arguments` 支持 `{selection}/{selection_sheet}/{stepN.属性}` 占位符（`stepN.*` 引用前一步实际产物做兜底对照）；6 个内置透视类流程已注入 `verify_pivot`（含 `sheet={selection_sheet}` 消除 ActiveSheet 依赖）；verify 工具未配置 Tool 时 fail-closed 阻断（VERIFY_NOT_CONFIGURED），不静默放行。已真机验证（VVT-B 全 PASS：通过/阻断/fail-closed 三态）。

### 3.4 脚本编排与状态

**目标**：让脚本执行具备「跨调用状态」与「多步编排」能力。

| 编号 | 需求 |
|---|---|
| D1 | **Python 持久状态**：worker 支持 `persist` 选项保留命名空间跨调用（默认隔离）；提供 `xai_state` 持久 dict |
| D2 | **VBA 持久状态**：独立状态模块 `JYYJXaiState`（创建后不再改写，模块级变量跨调用保留）；每轮新建唯一运行模块 `JYYJRun_<guid>` 承载辅助块+片段，执行后整模块移除（不触发整工程重编译，状态不丢）；提供 `XaiState` 读写辅助 |
| D3 | **多步编排**：复用 `run_workflow` 组合「读→算→写」多步；步骤间数据经 3.2 数据通道传递 |
| D4 | **状态护栏**：持久状态有生命周期（会话内/显式清除）；`state_clear` 显式清空；超时重建/升级后 `state_reset=true` 提示旧状态已丢失；不落盘（仅内存） |

**验收**：第一次调用设 `xai_state["x"]=1`，第二次（`persist:true`）读到 `x=1`；未开 `persist` 两次调用隔离；「Python 算→VBA 写」经 `run_workflow` 串联成功；显式清除/会话结束状态清空。

### 3.5 侧边栏 Python 脚本面板（PT 面板，第 6 个面板）

**目标**：终端用户在侧边栏直接编写 / 粘贴 / 运行 Python 代码，无需进聊天，与 VBA 面板能力对齐。

| 编号 | 需求 |
|---|---|
| E1 | **6 面板布局**：聊天 / 公式 / VBA / Python（PT）/ 流程 / 设置；Python 面板含代码编辑器、运行模式、模板库、执行选项、结果展示、AI 分析 |
| E2 | **双模式切换**：`纯计算`（run_python_code）不自动连接 Excel、直接执行免确认；`Excel 读写`（run_python_excel）为 Dangerous，执行前原生代码确认框 + 可选 `write_ranges` 回滚 |
| E3 | **模板三源一套**：预置 / AI沉淀 / 手写共用 CustomToolStore，按 `python` 标签过滤展示，与 VBA 模板双向隔离（VBA 面板滤掉 python 标签、Python 面板只收 python 标签、Python 保存自动追加 python 标签）；预置模板读写「活动表」（`sheets.active`）而非第一张表 |
| E4 | **执行选项**：persist 持久状态（与 run_python_code / run_python_excel 共享 worker 命名空间、变量互通）；state_clear 显式清空；插入选区写入 `# XAI_SEL:` 标记与 `sel_range` 变量 |
| E5 | **校验与分析**：`ValidatePython` 用 `python -m py_compile` 编译不执行、剥离绝对路径噪声、15s 超时；`AnalyzePython` 五小节结构化分析 + 提示词注入防护 |
| E6 | **安全边界**：纯计算模式为用户主动执行路径，绕开 AI 代理确认门（run_python_code 注册为 Dangerous，AI 路径仍走确认门），受控执行总开关仍生效；前端明确提示「纯计算具备文件/网络等系统能力，请勿粘贴不可信代码」 |

**验收**：面板 6 个导航齐全；双模式切换正确；纯计算直接执行并结构化返回；Excel 模式经确认后 xlwings 写回、未确认不执行；模板按 python 标签双向隔离；py_sum_range 预置在活动表求和正确；py_chart_selection 预置按选区画柱状图可跑。

## 四、安全契约（全期通用）

| 项 | 契约 |
|---|---|
| 风险分级 | `run_python_excel` 与 `run_vba_snippet` 同级：Dangerous + 确认门 + 受控执行总开关；`run_python_code` 注册为 Dangerous（AI 代理路径经确认门），面板「纯计算」为用户主动执行路径可免确认（见 3.5 E6） |
| 数据护栏 | 入参数据量上限（10 万 cell 量级）；结构化回传体积上限（默认 1 MB） |
| 写回纪律 | Python/VBA 直写 Excel 均绕过 `OperationRecorder`，靠确认门兜底；AI 声明 `write_ranges` 时执行前快照该区域供回滚 |
| 依赖安装 | pip 安装需用户确认；镜像兜底（国内默认清华/阿里，失败自动切换）；系统目录装不进自动退 `--user`；装后 `import` 自检；失败分级提示（无网络/权限/版本不兼容），不静默降级 |
| Python 版本校验 | `run_python_excel` 首次使用先 `python --version` 探测：低于 3.9 或位数与 Excel 不匹配（COM 直连要求 64 位 Python ↔ 64 位 Excel）时，给出明确安装指引（装 64 位 Python 3.10/3.11 并勾选 Add to PATH），不撞 COM 连接失败 |
| 新增工具纪律 | 工具名先 `rg` 查重防 CS0111；schema 参数名与前端确认门字段一致 |
| 交付闭环 | 实现 → 单元测试（0 警告 0 错误）→ 真机 COM 冒烟；升版本同步核对硬编码期望版本常量 |

## 七、开放问题（需真机验证后定稿）

1. **xlwings 连接活动 Excel 实例的可靠性**：`xw.apps.active` 对「非 xlwings 启动的 Excel 实例」的连接成功率，pywin32 `GetActiveObject` 兜底路径是否必要。**已定稿**：真机验证（VerifyP3Review P3R-3）确认——harness 以 COM ProgID 直接创建 Excel 实例（非 xlwings 启动），`run_python_excel` 经 `xw.books.active` 成功附着并写回 D1=99，连接稳定。xlwings 引擎内部已通过 pywin32 处理运行实例附着，**自定义 `GetActiveObject` 兜底不必要**。
2. **Python 直写 Excel 的撤销策略**：本期快照声明区域是否足够，完整撤销方案是否值得投入。**已定稿**：真机验证（VerifyWriteRanges VWR-1/1b/2）确认——AI 声明 `write_ranges` 时执行前快照目标区（C# 直读 COM），执行失败/异常自动回滚恢复原值（VWR-2 实测 xlwings 写 999 后抛异常 → F1 恢复初始 123 且返回「已自动回滚」）；不声明 `write_ranges` 时 xlwings 写入对 C# 连接可见（VWR-1b 实测 F1=99 被 C# 读到，验证 C# 与 xlwings 同实例读写一致）。**决策：维持现状（声明区域快照 + 失败自动回滚 + 原生确认门 + 受控执行总开关），不投入完整撤销**——与 VBA 直写策略一致（VBA 亦无撤销，靠确认门兜底）；完整撤销需将 xlwings 写回纳入操作历史，Python 进程直写无法被 C# 可靠拦截追踪，投入产出比低。
3. **VBA JSON 序列化器实现**：自研轻量序列化器的转义正确性，是否可复用现有 C# 侧 JSON 逻辑。**已定稿**：真机验证（VerifyP3Review P3R-6）确认——自研 `XaiJson`/`XaiEsc` 对系统代码页可表示字符（中文/双引号/反斜杠/换行/Tab）经 `XaiReturn` 完整往返、逐项一致，转义正确性成立。emoji 等非 BMP 字符在中文系统经 VBE 模块注入层即被 ANSI/GBK 替换为 `?`（诊断分支证实 VBA 直写单元格同样损坏，非序列化器缺陷），已作为已知限制写入 `run_vba_snippet` 描述。C# 侧 JSON 逻辑不可复用（VBA 侧无 System.Text.Json），保留自研实现。
4. **持久状态与 worker 重建**：进程崩溃/超时重启后持久状态丢失的提示语义。**已定稿**：真机验证（VerifyP3 P3-D2/D4、VerifyP3Review P3R-2a~2e）确认——`state_reset=true` 在三种场景可靠回传：①首次 persist 建上下文时（P3R-2c' 前）；②`state_clear=true` 无条件回 true（persist 与否都兑现，P3R-2a/2b）；③worker 崩溃/超时重建后首次 persist（`_persist_globals` 归零，P3R-2d 实测）。AI 据此丢弃旧状态认知；状态仅存内存不落盘（无状态文件残留）。语义已闭环，无需额外改动。
5. **Python 依赖安装的离线场景**：无网络环境下的降级路径（手动安装指引）是否够用。**已定稿**：代码审查确认 `InstallDeps` 分级降级链完整——清华→阿里→默认 PyPI 镜像兜底，系统目录失败退 `--user`，装后 import 自检；全源失败按 `no_pip`/`permission`/`network`/`unknown` 四级分类给出可读提示，每类均附**手动 pip 安装命令**（如 `python -m pip install xlwings pywin32`）。离线/无网络即命中 `network` 分支：提示检查网络 + 手动安装指引，作为降级路径已充分（真实断网无法在本机复现，由代码路径 + 单测覆盖）。
6. **VBA 执行无看门狗超时**：`run_vba_snippet` 经 COM 同步 `Application.Run` 执行用户代码，无法从外部安全中断——用户代码若死循环（如 `Do: Loop`、`For i=1 To 1e9`），会一直占用 Excel 直到用户在 VBE 手动按 Esc 中断。静态闸门（PreRunVbaGate）能拦截未闭合引号、2D AutoFit 等必失败写法，但无法静态判定死循环。缓解策略：工具描述明确「代码必须能在数秒内自行终止」；AI 生成侧避免无界循环；真机冒烟覆盖非死循环场景即可。已记录为已知限制，不做运行时中断（架构性不可行）。
