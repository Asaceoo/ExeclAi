## 2. 核心结论

### 2.1 开源三库格局（Python 生态）

| 库 | 定位 | 图表能力 | 局限 |
|---|---|---|---|
| openpyxl | 读写兼备 | 基础图表族，组合图 `bar += line` | 高级定制繁琐 |
| XlsxWriter | 仅写新文件 | 图表最强：custom data labels、Sparkline、雷达/股票图 | 不能改现有文件 |
| xlwings | 附着运行中 Excel | COM 全量（透视/宏/切片器） | 依赖本机 Excel |

**"原生动态图表"定义**：图表存于 xlsx 内部绑定单元格区域，改数据自动刷新——与本项目 COM 方案目标一致且更强（可改用户当前工作簿）。

### 2.2 与本项目方案的相互印证

| 开源/社区做法 | 本项目对应设计 |
|---|---|
| CSDN 实战项目：计算结果写隐藏 sheet（KPI_Summary_Hidden），图表 Reference 指向隐藏区 | SUMIFS 辅助区方案 ✓ |
| 附带 Dashboard_Template 模板工作簿（预设位置/坐标/条件格式），脚本传参填数 | DashboardSpec 布局默认值 ✓ |
| Vega-Lite NL→spec→schema 校验→渲染（学术+工程收敛） | DashboardSpec 架构 + 三级校验链 ✓ |
| 微软 Copilot Agent 模式：NL→计划→内建工具改工作簿，可回滚 | 幂等重生成 + 删除即回滚 ✓ |
| 杰瑞 67 套传参模板 + 选型 SKILL | 模板目录 + 图表选型内置技能 ✓ |

**判断：DashboardSpec"AI 出结构化规格 + 确定性引擎执行 + 失败可校验"是行业收敛点，非独创冒险。**

### 2.3 关键事实：切片器是文件级库的公共盲区

openpyxl/XlsxWriter 均无法创建原生切片器；官方生态 = PivotTable + Slicer + Report Connections（一键关联全部图表）。**cell 模拟联动（SUMIFS+数据验证）是文件级方案的行业普遍被迫选择**；native 切片器若 P0 真机探测通过，将是超越 Python 生态的能力增量。

### 2.4 生态位（竞品格局）

| 方案 | 原生 xlsx | 用户当前工作簿 | 备注 |
|---|---|---|---|
| 微软 Copilot Agent | ✓ | 仅 365 网页版 | 订阅+通道锁死 |
| 千问表格 Agent | ✓ | ✗（云端生成下载） | 沙箱 coding 路线 |
| ChatExcel Max | ✓ | 部分支持 | 云端 |
| Web BI（Grafana/积木） | ✗ | ✗ | 大屏生态 |
| **JYYJ 本方案** | **✓** | **✓ 进程内 COM** | **数据不出工作簿，无人占据** |

## 3. 已采纳的修订（写入设计文档）

1. **§4.1 三级校验链**：L1 spec 静态校验（字段白名单 + 类别数上限预检 + schema）→ L2 渲染期分级错误 → L3 verify_dashboard fail-closed；吸收 compile-before-render 思想；
2. **§5.3 选型规则表**：数据形态→图表映射固化（含 ≤5 类环形上限、Top10 截断、特大值→截断柱），原则"拒绝并给替代建议"而非静默降级；
3. **§5.4 KPI 卡三件套**：数值主体 + 环比箭头（▲▼+条件格式红绿）+ 可选迷你趋势；**比率类一律 IFERROR 包裹由渲染引擎强制注入**。

## 4. 明确不借鉴的

- matplotlib 出图嵌入 Excel（静态截图不可编辑，反向印证"非图片嵌入"硬约束）；
- 云端沙箱生成整个文件再下载（脱离用户工作簿，联动断、数据搬家）；
- Web BI 大屏路线（非 xlsx 原生生态）。
