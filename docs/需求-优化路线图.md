## 0. 竞品对标结论（为什么是这几个方向）

| 竞品 | 定位 | 比我们强的地方 | 我们比它强的地方 |

| OfficeCLI（32.9k★，C#） | AI Agent 专用 Office CLI，三层抽象（L1 语义视图/L2 元素操作/L3 XML 兜底） | 通用元素操作层覆盖长尾场景；单二进制免装 Office | 我们深度绑定活动工作簿、有 verify_* 自检与回滚 |

## P0（红线缺口 + 战略级，先做）

### P0-1 MCP/CLI 审计与回滚接入（收 N3）
- 现状：两入口均 `new ExcelToolHost(app)` 单参构造 → operationRepository=null → 写操作无审计、undo_excel_operation 不可用。
- 改法：McpServer/CliServer 启动时构造 OperationRepository(dbPath 指向 %AppData%\ExcelAiAssistant\operations-mcp.db)，传入宿主四参构造；验证 undo_excel_operation 与覆盖审计在两入口生效。
- 验收：MCP/CLI 执行 write → get_operation_history 有记录 → undo 成功恢复；AC-M4 无进程残留复测。
- 估时：0.5 天。

### P0-2 L2 通用结构操作层（对齐 OfficeCLI）
- 新增工具族（预计 6 个）：`query_elements`（按谓词查区域/形状/表/图表）、`get_element`、`set_element`、`add_element`、`remove_element`、`move_element`。
- 价值：一个通用层顶掉长尾专用工具需求；LLM 组合能力强于枚举 156 工具。
- 约束：全部走既有 RiskLevel 分级与守卫；schema 用 M3ToolSchemas 帮助方法；入覆盖审计。
- 估时：2 天。

### P0-3 确认门强制力（收 N1，与 P0-2 配套）
- 现状：MCP requires_confirmation 是 AI 自答式（客户端不渲染）。
- 改法：MCP server 启动加 `--confirm-dir <path>`——Dangerous 工具首次调用生成唯一确认码文件（含工具名/参数摘要），客户端必须带 `confirmed=<code>` 才放行；CLI 同款 `--confirm-code`。人工从文件读码输入。
- 验收：无确认码不放行；确认码一次性（用后作废）；与现有 confirmed=true 语义兼容开关 `--legacy-confirm`。
- 估时：1 天。

## P1（差异化 + 分发，战略收益大）

### P1-1 草稿模式（对齐 Univer worktree）
- 场景：AI 大改前先生成隐藏副本 sheet（前缀 draft_），在副本执行全部变更，产出 diff 预览（单元格级 before/after 表格写进对话），用户「采纳」→ 复制回正式 sheet + 删草稿；「放弃」→ 删草稿。
- 复用：撤销快照基建、保护态守卫、verify_*（草稿上也跑自检）。
- 新工具：`start_draft` / `diff_draft` / `apply_draft` / `discard_draft`（4 个）。
- 估时：2 天。

### P1-2 npm 包分发（对齐 xlsx-for-ai）
- npm 包 `jyyj-mcp`：bin 入口下载/定位本机 ExcelAiMcpServer.exe（按版本从 GitHub Releases 拉），生成 claude_desktop_config 片段打印；CLI 同包 `jyyj-cli`。
- 上架 claude.ai connector directory（MCP 规范）。
- 验收：干净机器 npx 一条命令 + Claude Desktop 出现 156 工具。
- 估时：1.5 天（含发布流程）。

### P1-3 外部数据源接入工具族（对齐 Data-Analysis-Agent）
- 新工具：`import_csv`（已有 TextEncodingDetector 复用）、`import_json`、`query_database`（SQLite/ODBC 只读查询→写临时 sheet）。
- 全部只读源、写入走既有写链（守卫+自检+回滚）。
- 估时：1.5 天。
