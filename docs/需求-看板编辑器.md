## 1. 背景与问题

FR-6 交付后，看板"生成→自检→联动→删除"链路完整，但**生成后的局部调整**仍只能整板重生成（D-③ v1 边界）。重生成的代价：

- 覆盖用户对看板的手工修饰（列宽/备注/手工格式）；
- 丢掉联动配置需要重建（native 切片器虽由渲染自动挂载，但手工调整的选择态会丢）；
- 大表重生成耗时（2 万行约 10 秒）且期间 Excel 被锁定。

用户实际诉求集中在三件小事：**换个配色、改一下行列映射、删掉某张不要的图**——都值得免重生成完成。

## 2. 目标与非目标

**目标**：看板生成后，用户可通过对话对已有看板做三类局部修改，全程自检兜底、可回滚、不留半成品。

**非目标（v2 明确不做）**：

- 自由拖拽布局 / 调整图表尺寸位置（v3 再议）；
- 图表类型互换（改型 = 删旧建新，用既有 delete_dashboard_chart + create_chart_advanced 组合表达）；
- 跨看板复制图表；
- 直接编辑单元格数据（写路径已有工具族覆盖）。

## 3. 功能需求

| # | 需求 | 说明 | 交互口径 |
|---|---|---|---|
| FR-E0 | 看板图表清单 | `list_dashboard_charts`（只读）：枚举指定看板的 ChartObject（名称/类型/锚点/系列数/数据源区域）+ 主题当前值。编辑前必调，AI 据此向用户复述现状 | "看看销售看板上有什么图" |
| FR-E1 | 换主题 | `edit_dashboard_theme`：仅重刷配色（KPI 卡底色/标题与数值字色/数据条/图表配色组），不重建 sheet、不碰公式；参数 dashboard_sheet + theme（orange/blue/graygreen） | "把销售看板换成蓝色主题" |
| FR-E2 | 换映射 | `edit_dashboard_mapping`：调整行列/系列映射（label/category/month/value/quantity 列位改指），重写 staging 公式与图表源引用并重算；参数支持逐列改指，改前用 suggest_chart_mapping 的画像给建议 | "销售看板改成按品类筛选，趋势看月份" |
| FR-E3 | 删单图 | `delete_dashboard_chart`：删除看板上指定 ChartObject（按名称，名称来自 FR-E0 枚举）；级联清理其专属辅助引用（若有）；StructuralChange 确认门 | "删掉销售看板里那张环形图" |

## 4. 约束（沿用看板族既有红线）

- 全部走 `SheetProtectionGuard` 前置探测；StructuralChange 级确认门；
- 每次编辑成功后自动跑 `verify_dashboard`（结论回显返回值，FR-6.3 同款）；
- 失败回滚不留半成品（AC-5 同源）；幂等语义明确（同参数重复执行结果一致）；
- staging `_calc` 公式改写沿用 RewriteStagingFormulasForNative 的规范化 needle 族（四种公式形态兼容）；
- 新工具照看板族接入清单全链表态：实现/Schema/注册/AutoVerifyPolicy/一致性测试/Md1Probe/技能映射/指南卡/双副本同步。

## 5. 验收标准

| # | 标准 |
|---|---|
| AC-E1 | 换主题后 verify_dashboard=ok，且 KPI 卡底色/字色实测变化（读单元格 Interior/Font 断言，非仅返回值） |
| AC-E2 | 换映射后 KPI 守恒对账通过（KPI 值 == 按 新映射 SUMIFS 重算值），切片器/下拉联动仍可用 |
| AC-E3 | 删单图后其余图表与 KPI 卡不受影响；staging 无悬挂引用（公式引用的区域仍存在）；图表计数守恒断言（删 1 减 1） |
| AC-E4 | 保护态工作簿上操作被守卫拦截并给出可读提示 |
| AC-E5 | 任意步骤 COM 失败时回滚，看板回到操作前状态（图表计数 + KPI 值前后一致） |
| AC-E6 | Md1Probe 真机用例覆盖三工具主路径 + 非法参数拒绝 + 回滚路径 |
| AC-E7 | **数值守恒**：换主题前后看板全部数值不变（KPI 卡值/图表计数不变）；删单图恰好 -1 且 KPI 值不变（防"编辑器顺手改数据"） |
