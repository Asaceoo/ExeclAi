# 功能扩展调研报告 · 还有哪些能力值得做

> JYYJ助手（v2.18.0.0）· 2026-09-06 · 基于本地能力盘点 + 行业竞品调研

---

## 一、核心结论

项目已具备 **126+ 工具、六大质量自检层、功能区一键直达、流程编排、技能包** 等成熟底座，二期工具清单已几乎全部落地。在此之上，仍有 **7 大差异化机会**，按「价值 × 可行性」排优先级：

| 优先级 | 能力方向 | 价值 | 可行性 | 对标 |
|---|---|---|---|---|
| **P0** | 多文件批量整合与一键汇总 | 极高（财务/运营刚需） | 高（已有 merge_workbooks/import 基础） | Copilot 分析代理、Julius AI |
| **P0** | 定时报表自动化 | 高（重复劳动刚需） | 中（需新增调度器+邮件） | 竞品普遍空白 |
| **P1** | 图片/截图 OCR 转表格 | 极高（发票/表单/截图） | 中（需接 OCR 引擎，离线有难度） | WPS AI |
| **P1** | 数据分析增强：趋势预测/异常洞察 | 高（已有分析报告底座） | 高（纯逻辑，可单测） | WPS AI、Julius |
| **P1** | 单元格级 AI 公式 `=AI()` | 高（公式化传播复用） | 中（需 UDF/COM 同步扩展） | Numerous.ai |
| **P2** | 数据血缘追踪 | 中（审计、财务场景） | 中（需记录公式依赖图） | Copilot Show Work |
| **P2** | 自然语言转 Power Query | 中（清洗逻辑可复用） | 低（需 M 代码生成器） | Microsoft Copilot |

**明确不考虑**：WPS 兼容（架构约束，硬伤）、语音输入（低优先级，键盘已够）、邮件发送（本质是 OutLook 集成，超范围）——详见第六节。

## 二、能力盘点：项目已是"尖子生"

### 2.1 已实现的能力全景（v2.18.0.0）

- **对话执行**：自然语言操作、选区引用、单轮工具上限可调（1-1000）
- **数据处理 60+ 工具**：读写/清洗/去重/排序(行守恒)/筛选/转置/透视(守恒对账)/异常标记/文本日期数字变换
- **分析可视化**：图表生成+渲染像素核验、迷你图、统计分析、分析报告
- **公式**：生成、逐层解释、引用转换
- **VBA/Python 双执行**：生成/静态校验/确认门/受控执行/自动沉淀为工具
- **流程编排**：多步模板、步骤级自检、失败单步重试
- **技能包**：内置 12 个，支持 SKILL.md 在线安装
- **跨工作簿**：只读引用、网页停靠窗格
- **安全回滚**：逐操作回滚+冲突保护+快照 SQLite
- **质量自检六层**：自动自检/verify_* 族/语义守恒/元自检/失败模式库/真机门禁(829 单测+63 断言)

## 三、P0：两个最该先做的能力

### 3.1 多文件批量整合与一键汇总

**为什么**：财务/运营每月汇总多部门表、多产品线报表是最高频刚需。项目已有 `merge_workbooks`/`merge_sheets`/`import_excel_file_sheet` 单文件入口，缺的是"拖入 N 个文件 → AI 自动合并/对比/生成汇总报告"的一站式批量流程。

**建议形态（贴合现有架构）**：
- 新增工作流模板「多文件汇总」：让 AI 先 `preview_external_file` 逐个盘点 → `merge_delimited_files` 或按规则合并 → `create_excel_pivot_summary` → `generate_analysis_report`
- 复用既有流程编排引擎（WorkflowStore）与 verify 自检，几乎零新基建
- 竞品对标：Copilot 分析代理跨文件比较、Julius 多 CSV 上传

**可行性**：**高**。核心工具已在，主要是"批量编排 + 文件列表参数"的组合封装 + 自检富化。

### 3.2 定时报表自动化

**为什么**：竞品几乎都没做好，这是差异化空白；"每周一自动汇总上月数据→生成图表→（可选）发送"是强痛点。

**建议形态**：
- 复用流程编排引擎 + 新增轻量调度器（Windows 计划任务或进程内 Timer，需遵循项目记忆：调度器日志禁止逐 tick 写日志）
- 输出落地为"生成报表工作簿"+ 可选导出 PNG/PDF，先不做邮件发送（见第六节）

**可行性**：**中**。调度器本身简单，难点在"无头打开工作簿/刷新数据/保存"的稳定性与错误上报，需纳入自检。

## 四、P1：三个能快速成型的能力

### 4.1 数据分析增强：趋势预测 + 异常洞察

项目**已有** `analyze_range_statistics` / `analyze_column_correlation` / `analyze_value_distribution` / `generate_analysis_report`（含趋势/相关性描述）。缺口只在**增量能力**：

- **趋势预测**：对时间序列做简单线性/移动平均预测（纯逻辑，C# 可单测，无需引外部引擎）
- **异常洞察**：IQR/标准差阈值自动标记，生成洞察章节

**可行性**：**高**，纯服务端逻辑，进自检可在 verify 层加判定。高贵值比。

### 4.2 单元格级 AI 公式 `=AI()`

对标 Numerous.ai，难点是涉及 UDF（COM 暴露，独立机制）与"计算时调模型"的同步性——Excel 公式引擎是同步的，而模型是异步的，需要做**缓存/异步握手/降级**。

**建议**：先做**受限版**——`=JYYJ.AI("分类", 单元格)` 对**纯文本分类/清洗**类确定性任务，用本地规则/小模型，避免公式内长阻塞。完整在线版作为远期。

**可行性**：**中**。UDF 注册是现成机制，但"公式内同步调模型"是本项目最大的架构张力，需单独论证。

### 4.3 图片/截图 OCR 转表格

对标 WPS 拍照。价值高（发票/试卷/表单/截图整理），但**离线 OCR 引擎引入**与项目"本地优先"哲学需权衡。

**建议**：接 Windows 自带 OCR（Windows.Media.Ocr，离线、无依赖、中文可）或本地 PaddleOCR，输出结构化表格到新工作表，再交给现有工具链分析。

**可行性**：**中**。风险点：识别精度、多线程/COM 线程约束（走 Python worker 更稳）。

## 五、P2：两个值得储备的方向

### 5.1 数据血缘追踪

财务审计需要"B145 ← =A10*2 ← C5"的公式依赖追溯。项目已有 `trace_formula_references`/`drill_excel_range` 的基础，可增强为**依赖图谱可视化** + 变更影响面提示。

**可行性**：**中**。数据量大时构图有性能挑战；与现有 verify 闭环可结合（写入后提示受影响单元格）。

### 5.2 自然语言转 Power Query

让用户描述清洗逻辑，自动生成可复用的 Power Query（M 代码），比 VBA 更易维护、更"官方"。但 M 代码生成器是全新领域，且项目已用 Python worker 承担了同类"可复用脚本"职责，**与 Python 沉淀能力存在定位重叠**。

**可行性**：**低**，建议观望，不急着做。

## 六、明确不做 / 延后（含理由）

| 方向 | 决策 | 理由 |
|---|---|---|
| WPS 兼容 | 不做 | 架构硬约束：VSTO/COM 仅 Excel，重写成本极高且方向反着走 |
| 语音输入 | 延后 | 键盘输入主场景已够；需额外音频处理栈，价值密度低 |
| 邮件/Outlook 定时发送 | 延后 | 涉及进程外自动化（Outlook COM）与安全边界，超本项目范围；先出"报表落地"版 |
| 云端账号/订阅授权 | 不做 | 首版锁定"本地+用户自带 Key"模型，商业化另行决策 |
| 自动联网搜索 | 延后 | 与"数据隐私/发送范围可控"的既有承诺有张力，需重新设计边界 |

## 七、落地建议（贴近项目 SOP）

结合项目自检体系与发版流程，推荐启动顺序：

1. **P0-1 多文件批量汇总**（快，复用现有工具，尽快出价值）
2. **P1 数据分析增强**（纯逻辑、可单测、高贵值比，与质量体系天然契合）
3. **P0-2 定时报表**（需调调度器，独立排期）
4. **P1 OCR / 单元格 AI 公式**（技术预研先行，各需论证一个架构点）

每个能力若要进入实现，均需走项目硬性约束：新增工具必入 `MappedPrimaryTools` 或 `DocumentedWriteToolExemptions` 覆盖审计、829 单测+真机 harness 63 断言、双关门禁打包。
