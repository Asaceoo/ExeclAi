# 数据能力对标调研：本项目 vs 主流成熟方案（2026-09-19）

> 对标对象：Microsoft Copilot in Excel、国产 ChatBI 阵营（帆软/衡石/瓴羊/观远）、对话式分析工具（Julius AI/pandas-ai）、WPS AI、Gartner 2026 ABI 趋势。
> 本项目基线：v3.8.1.97（分析族 9 工具 + Python 18 任务路由 + 图表看板族 + 三报告宏 + 质量底盘）。
> 结论先行：**本项目在「写入回工作簿 + 确定性自检 + 离线运行」三点上领先同类；最大差距集中在「口径记忆、自动归因编排、主动预警」三项组织级能力。**

---

## 一、主流方案能力画像（检索实证）

### 1. Microsoft Copilot in Excel
- 三模式分层授权：**Chat only / Plan（先出计划确认再动） / Allow editing**；Agent Mode 支持多步骤任务规划执行 [ref: Microsoft Learn 高级分析模块]
- Python in Excel + **think deeper**（复杂问题先生成结构化分析计划再执行）；**Analyst agent** 跨多文件对比分析后再进 Excel [ref: Microsoft Support]
- =COPILOT() 函数把 AI 嵌进单元格；公式生成带逐段解释（explainability）[ref: WindowsForum 汇总]

### 2. 国产 ChatBI 阵营（帆软/衡石/瓴羊/观远）
- **NL2Metrics（指标语义层）**成为头部路线：AI 在预定义指标上作答而非直译 SQL，衡石复合查询首次准确率 96% vs 行业 78% [ref: 衡石/未央网 ChatBI 榜单]
- **三级溯源**：L1 指标层（口径定义与版本）→ L2 模型层 → L3 数据层，每个回答可逐层下钻验证 [ref: FineBI 横评]
- **业务记忆**：自动学习指标口径/业务规则/输出偏好，跨会话持久化——「没有记忆的 AI 问数是一次性工具」[ref: FineBI 横评]
- **Skill 沉淀**：一次验证的分析路径（取数→拆解→归因→报告）封装为 Skill，全公司一句话复现 [ref: FineBI 横评]
- **自动归因**：问「为什么下降」自动多维下钻到 SKU/门店级，约 12 秒定位根因；**主动预警**异动推送到 IM 并附原因解读 [ref: 未央网]
- **多智能体分工**：问数/建模/解读/报告四 Agent 协同 [ref: 未央网]

### 3. 对话式分析工具（Julius AI / pandas-ai）
- **代码可见（show its work）**：每个结果附生成的 Python/R 代码，用户可校验「分组字段是否选错」——被评测者列为最有价值特性 [ref: DataStudios/aitoolbox Julius 评测]
- **自纠错执行**：代码报错自动调整重试而非让用户重问 [ref: DataStudios]
- **Notebooks 可复用工作流**：把「每周销售报告」固化为可重复执行的模板；prompt 模板库 [ref: eesel/aitoolbox]
- 多源连接（Snowflake/BigQuery/Postgres）、报告导出为可交付文档

### 4. WPS AI（同赛道直接竞品，SpreadsheetBench V2 第一 50.86%）
- 能力面：写公式/透视/趋势/异常/图表推荐/公式逐层解释——**与本项目高度同构**；差异化在端侧推理与隐私脱敏、JSON Schema 分析模板导出 [ref: WPS 官网/湖北日报]

### 5. Gartner 2026 ABI 魔力象限
- 「**到 2027 年 60% 企业把『从自然语言到自动化行动』列为采购核心标准**」；「60% 无治理语义层的 agentic analytics 项目会失败」；mandatory features 含 agentic insights / conversational analytics / audit trails [ref: Gartner MQ reprints / ThoughtSpot 解读]

## 二、差异矩阵（本项目 v3.8.1.97 实测能力 vs 上述标杆）

| 能力维度 | 本项目现状 | 标杆水平 | 差距定性 |
|---|---|---|---|
| 分析结果写回工作簿 | ✅ 强项（直接写入+撤销快照+守恒对账） | Copilot 静态表/图插入不可刷新；ChatBI 只出图表 | **领先** |
| 统计深度 | ✅ 检验/回归/聚类/时序（C#+Python 双层） | Copilot 依赖 Python 云容器；WPS AI 明确不做 | 持平偏上 |
| 确定性自检 | ✅ 独有（basis 计算依据/守恒对账/读图自审/确认门回滚） | Julius 代码可见接近；ChatBI 溯源是查询层非计算层 | **领先** |
| 口径治理 | 🔶 `_口径.md` 手动文件+契约 | 指标语义层+自动学习记忆+三级溯源 | **差距 1（最大）** |
| 自动归因编排 | 🔶 宏 prompt 编排（深度分析/洞察分析），无独立工具 | 「为什么下降」一键自动多维下钻 | 差距 2 |
| 主动预警/定时 | ❌ 无（被动问答型） | 异动监控→IM 推送→附建议 | 差距 3 |
| 交互分层授权 | 🔶 风险分级确认门（写操作） | Chat/Plan/Edit 三模式显式呈现 | 小差距 |
| 工作流复用 | ✅ 已有（32 宏+技能市场+模板三源） | Julius Notebooks / FineBI Skill | 持平 |
| 多文件跨簿 | 🔶 read_external_range 只读句柄 | Copilot Analyst agent 跨文件对比 | 小差距 |
| 错误自愈 | 🔶 缺库自愈闭环 | Julius 代码级自纠错 | 小差距 |

### 不建议跟进的方向（有意保持差异）
- **云端多源数据库连接**（Snowflake/BigQuery）：本项目定位本地 Excel 办公场景，引数据库连接层改变产品边界且涉及安全面扩大
- **NL2SQL/数据中台**：ChatBI 是组织级 BI 底座产品，与单机助手形态不匹配
- **AI 嵌单元格函数**（=COPILOT()）：需 XLL/UDF 通道（函数库线暂停中，且重算线程调模型违反确定性红线）

## 四、核心结论

1. **护城河是「可信执行」**：主流方案在「结果写回+自检+回滚」上普遍薄弱（Copilot 插入的是不可刷新静态物），本项目这套「确定性计算+守恒对账+读图自审」底盘应对 Gartner「audit trails/governed autonomy」趋势是顺风的，应持续强化宣传口径。
2. **最大差距是「组织记忆」**：口径/规则/偏好的自动沉淀与复用是 2026 年 ChatBI 分水岭，本项目的 `_口径.md` 已有正确雏形，差「自动沉淀」一步。
3. **最快见效是 #1+#2+#3**：三项合计 ~2 天，全部复用现有基础设施（口径文件/分析族/调度/宏体系），把「被动问答工具」补齐为「带记忆、能归因、会体检的分析助手」。
