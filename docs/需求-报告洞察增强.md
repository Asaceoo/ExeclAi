# 需求：报告洞察增强（让报告更富洞察力、更详实、更全面）

> 版本 v0.1（2026-09-15，grill-me 八问冻结）。**默认拍板声明**：本稿按助手推荐项超时默认冻结（同 Q2 图表单入口先例），未经用户逐条显式确认，任一条有异议可回滚重议。

## 一、背景与问题

报告链路现状：六章节固定模板（sections 白名单选子集）+ 聊天 AI 六段式叙述，两条线未合一。已知边界：①聊天洞察不进落盘报告；②不主动找对比基线，缺对比时静默；③无基线/目的注入，业务建议段偏通用；④报告生成后无自检守门；⑤纯文字无图。

## 三、使用侧实操清单（零代码，随 P0 批次沉淀进用户手册）

1. **业务口径前置**：数据同目录放 `_口径.md`，写业务规则与数据背景（口径命中后所有结论强制引用原文）；
2. **开场声明分析目的**：一句话说清"分析为了什么决策"（聊天叙述的报告建议段即有靶子）；
3. **提供对比基线**：上月/同期/目标数据放工作簿内或明确给出——报告立刻从"绝对值描述"升级为"对比洞察"（Q4 落地前手动给、落地后自动探测）；
4. **复杂问题走「深度分析」宏**：Top-3 方法复述确认制，选中的才深挖；
5. **视角适配受众**："用财务/CEO 视角重跑"——指标框架与话术整体切换；
6. **要正式报告时声明受众与用途**（汇报给老板 / 自查用）；
7. **让聊天洞察进报告（Q2 落地前过渡法）**：生成报告后补一句"把刚才的解读第 X 点也写进报告"；
8. **行使核账权**：抽查报告关键数字的来源区域——数字全部可回表对账是本产品报告与通用 AI 报告的核心差异。

## 四、开发批次路线（待用户启动后逐批实施）

- **P0-1（Q4）**：detect/报告链路自动探测基线列（同期/目标/预算语义），有则算同环比/达成率入报告；无则在报告"数据概览"段显式声明无基线；
- **P0-2（Q6）**：generate_analysis_report 生成后自检回显（数字对账/空段/覆盖匹配），对齐图表 auto_check 治理口径；
- **P1-3（Q2）**：报告工具新增 AI 洞察段机制（AI 叙述与落盘报告共享一次分析上下文，解读段带依据引用）；
- **P1-4（Q5）**：purpose 参数 + sections 现有白名单联动；
- **P1-5（Q3）**：内置可选章节四件套（勾稽核对/同环比对比/分群解读/假设与验证）；
- **P2-6（Q7）**：HTML 报告嵌图。

## 五、验收口径（草案）

- 报告含对比时：每个同环比数字可回表对账；报告无基线时必有显式声明（变异测试：注入无基线数据 → 声明必须出现）；
- 自检：注入空段/篡改数字的负例必须被自检抓到（对齐 verify_dashboard_deep U29 篡改必抓先例）；
- 使用侧清单进用户手册并随版本戳同步。
