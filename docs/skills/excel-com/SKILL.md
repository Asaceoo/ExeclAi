# Excel 活工作簿协作（COM 语义）

本加载项直接操作「用户 Excel 里正在打开的工作簿」，与 openpyxl 那种另开一份 .xlsx 副本的方式不同。所有读写都必须走本加载项已注册的 COM 工具，不要假设可以脱离 Excel 进程操作文件。

## 1. 读取（分析前先看清数据）

- 复制一个包的描述：用 `read_excel_range` / `get_selection_val...` 等读取工具，先读取目标区域，再做大范围分析；不要凭用户一句话就动工。
- 大区域读取一次性整体取回（底层整体赋值），不要在循环里逐格 `Value` 访问。
- 读回的数据先把列类型看清楚（数值/文本/日期），日期若被转成数值要按文本列处理，别误判类型。
- 选区可能多块：先确认选区是否单块矩形；非矩形或多块时提示用户「请选择矩形区域」。

## 2. 写入

- 区分三种写入语义：写**值**（最终结果）、写**公式**（`=` 开头，可联动追溯）、写**格式**（仅改外观）。写前明确用户要哪一种。
- 批量写入用数组整体赋值到 `Range.Value`，严禁在 For 循环里逐格写入。
- 只改外观样式的操作（居中、字体、颜色、边框、列宽/行高、数字格式）只改 `Format` 相关属性；**严禁** `Clear`/`Delete`/覆盖原数据——保持选区内数值与内容完全不变。
- 需要写空格/缺省时：空格超过 5000 个要先提示「仅处理前 5000 空格，其余忽略」；无语义依据的空格填「待补」。

## 3. 公式生产

- 先读目标区与参考区，理解需求再生成公式；生成的公式要能配合「向下/向右填充」沿相对/绝对引用扩展（`$A$1`、`A1` 混用）。
- 输出习惯：先给一句说明（调用函数、参数含义、执行顺序），再给以 `=` 开头的单条公式，不写多余套话。

## 4. VBA 代码分析 / 命名

- 用户在 VBA 面板点「AI 分析当前代码」时，按固定五小节输出：**功能概述 / 关键逻辑 / 潜在问题（含性能与健壮性）/ 优化建议 / 建议命名**。
- 命名规范：过程/函数名用字母或下划线开头（不能用数字/中文开头做标识符，避免歧义），简短表意（如 `汇总本月销量` → `SummarizeMonthlySales` 或 `月销汇总`），一眼能看出用途；涉及选中区域操作的，名字里体现「当前选区」语义。
- 分析时若代码在循环里逐格读写、或缺 `Application.ScreenUpdating=False` / `Calculation` 手动模式，必须点出并给出数组整体读写的改法。

## 5. 沉淀

- 成功执行一段自写 VBA 后，主动调用 `save_vba_tool` 把代码沉淀为可复用工具（给出唯一合理的 name、用途 description、完整 code），是否保存由用户确认。
- 通用化建议：把代码里固化的区域（如 `Range("C5:F22")`）改写为「当前选区」占位符，换数据仍可复用。

## 6. 错误与边界

- 空选区 / 无非空数据：先提示用户选择区域，不要空跑。
- 工具调用结果失败会带 `error_code`，用它对用户解释原因，并把真实错误正文记入运行日志。
- 输出语言跟随用户：用户用中文就用中文，用英文就用英文。
