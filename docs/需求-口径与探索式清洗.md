## 1. 背景与机会

grill 调研发现三个跨工具族的共性缺口，均有开源界成熟范式可循：

1. **业务口径风险**：AI 生成的看板/分析结论可能"数对但口径错"（如毛利是否含税、活跃用户定义）。开源 GenBI 引擎 WrenAI 用文件化知识规则（knowledge/rules/）约束 AI，用户业务口径散落在文档/wiki 里时尤其有效。
2. **探索式清洗缺口**：本项目 clean/dedup 是"操作式"（用户指令→执行），缺 OpenRefine 的"探索式"体验（先摊开维度值分布、聚类疑似变体，用户确认后合并）。实测证据：OpenRefine 指纹聚类对中文公司名变体的识别准确率 98.7%，显著优于 Excel 精确匹配去重的 89.2%。
3. **分析结论透明度**：PandasAI 以 last_code_executed 让用户核对 AI 实际执行逻辑；本项目 verify_dashboard_deep 已实现图表级依据回显，但 analyze_* 分析工具的结论未附计算依据。

## 2. 功能需求

| # | 需求 | 说明 | 对标 |
|---|---|---|---|
| FR-K1 | 业务口径规则文件 | 工作簿同目录支持 `_口径.md`（Markdown，Git 友好；随业务文件走——开放问题 Q1 默认案）：**格式规范：每行一条 `- 术语: 定义`**，AI 才能逐条引用原文。读取与注入落点：SKILL.md 契约约定 AI 在生成看板/分析结论前用 read_file 读取（**读取上限 200 行/8KB，超出截断并提示用户**），涉及关键数值的回复逐条引用口径条目原文。**冲突优先级：用户当次指令 > 口径文件**，且 AI 发现冲突时必须向用户明示差异，不得静默择一。文件不上传云端。 | WrenAI knowledge/rules |
| FR-K2 | 文本列变体聚类建议（探索式清洗） | detect_dashboard_data_readiness / analyze 列画像升级：对文本列输出**疑似变体组**（算法分层：分隔符/大小写归一化 + 编辑距离 ≤2 为主——对中文公司名后缀差异有效；指纹算法仅对拉丁字符有效，不做中文承诺；C# 本地纯函数无新依赖）。每组给"代表值 + 变体成员 + **合并方向选项**（取最长/取最短/取出现最多，用户选）"。**合并动作 = write_excel_cells_batch 精准改写变体单元格为代表值（改值语义），不得用 dedup_range（其语义为删除重复行，见实现者审查①）**；走确认门+可回滚。 | OpenRefine Cluster |
| FR-K3 | 分析结论附计算依据 | 分析族工具（analyze_column_profile / analyze_value_distribution / analyze_range_statistics / analyze_column_correlation 等，实名见 ExcelDataToolsRegistration）返回值新增 basis 字段：**数值结论** → 公式文本/聚合口径/明细行号区间；**文本结论**（如"最多的是 X 类"） → 样本统计口径 + 计数来源区间；与 verify_dashboard_deep 的 expected/actual/basis 三件套形态对齐，SKILL.md 契约同步要求 AI 转述。 | PandasAI last_code_executed |

## 3. 约束（继承看板族既有红线）

- 全链路仅 Excel 宿主；聚类为 C# 本地纯函数实现，不引入新 NuGet 依赖、不联网；
- 口径文件仅本地读取，禁止随工具返回值整文外发（只摘录与本次结论相关的条目，防大文件撑爆上下文）；
- FR-K2 合并动作必须走 Dangerous 确认门 + OperationRepository 可回滚；
- 所有新工具入 MappedPrimaryTools 表态或显式豁免（发布门禁既有义务）。

## 4. 验收标准

- AC-K1：无口径文件时行为与现状完全一致（**验证方法：全量单测 + full 真机套件回归全绿**）；有文件时，让 AI 计算"毛利"，最终回复必须引用口径条目原文（人工核对引用与文件一致）；
- AC-K2：含 3 组变体（每组人为标注真值，组分隔符/后缀差异）的 1 万行样例，**召回定义 = 建议组覆盖真值组的比例 ≥95%**（测量：人工标注真值组 → 跑聚类 → 比对），AI 确认后合并结果可一键回滚（回滚后逐单元格比对与原始一致）；
- AC-K3：analyze 工具任一数值结论均可回溯到公式文本与明细行区间（真机抽样核对）。
